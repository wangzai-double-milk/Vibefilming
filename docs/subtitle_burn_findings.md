# 字幕烧录调研结论（留给后续做字幕的版本）

> 本版本（只剪辑）**不做字幕**，skills 已标注「字幕禁用/本版不做」。
> 本文件只是把 2026-06 灰度测试查明的根因和正确方案记下来，避免下次重新踩坑。**当前不要据此改 skills 或工具。**

## 一、纠正一个早期误判
内置 `imageio_ffmpeg`（本机 v7.1, macos-aarch64）**不是裁剪版**。实测带：
- 滤镜：`drawtext` / `overlay` / `ass` / `subtitles` / `scale` / `fps`
- 编码器：`libx264` / `png` / `mjpeg` / `gif`
- buildconf：`--enable-libfreetype --enable-fontconfig --enable-libharfbuzz --enable-libass`

所以「ffmpeg 没有 drawtext 所以烧不了字幕」这个早期结论是错的。字幕能力是有的。

## 二、上次字幕「全军覆没」的真正根因（三个，叠加）
1. **没指定字体**：不传 `fontfile` 时 fontconfig 报 `Cannot load default config file`，长句里相当比例的汉字被渲染成豆腐块 `□`。短词（如「沈玥的世界」）碰巧没踩到，于是表现成「有的能用、有的不能用」的随机失败假象。
2. **整段台词塞成一条字幕**：上次调用把几十个字的整段独白当成 `text` 一次性挂 6 秒，`drawtext` 不会自动换行，横向冲出画面宽度，首尾被截断。这是「字幕设计模型就错了」，不是渲染参数问题。
3. **`-vf` 内 `\n` 被解析成字母 n**：想手动折行时换行符会被当普通字符印进画面。

补充：上次 4 次 `burn_subtitle` 其实都**返回成功路径**了（不是抛错），生成了 `composed_sub1~4.mp4`，只是内容是豆腐块+截断的废片。所谓「卡死」更可能是 agent 看到成片不对、反复重烧重审导致的死循环。

## 三、字幕的正确模型（核心结论）
字幕不是「把一段话压在画面上」，而是一串**短时码 cue**：谁说话、说哪一句、在第几秒到第几秒出现，一行短到能放下，说完即消失。例如：
```
00:00.0 → 00:02.1  我是在赵建恒的淘宝订单里
00:02.1 → 00:04.3  发现成堆的孕妇用品
00:04.3 → 00:06.0  才意识到他可能出轨
```
现在 `burn_subtitle(text, start, end, ...)` 的签名本身就是错的——它鼓励「整段一条」。

## 四、正确实现路线（下次照此做）
1. **生成 SRT 时码文件**，用 `subtitles=xxx.srt` 滤镜烧（libass），自动折行/定位/按时码切换/多 cue，全部交给 libass，比手搓 `drawtext` 干净得多。
2. **难点是时间轴对齐**（这才是「字幕难」的真正原因，不是烧录）：
   - 简单够用：按分镜表每个镜头的时长，把该镜头台词**按字数比例切分**成 cue。
   - 精确但重：对成片音轨跑 ASR / 强制对齐拿逐句时间。
3. 工具签名应改成接 **cue 列表 / SRT**，而不是 `text + start + end`。

## 五、临时验证过的「机械层」配方（仅备查，非最终方案）
如果哪天只想快速烧短字幕而不上 SRT 流程，下面这套经 VLM 审核为「完整、清晰、无乱码、无截断、可用」：
- 字体：`fontfile=/System/Library/Fonts/STHeiti Medium.ttc`（单一字体文件；**别用 `PingFang.ttc` 合集**，drawtext 选不准字面仍出豆腐块）。
- 文本：写进临时 `.txt`，用 `textfile=` 传入，彻底绕开 `-vf` 转义（解决 `\n` 变 n）。
- 折行：竖屏约 13 字/行预折行，多行底部居中。
- 注意：这只是把「一面字墙」叠整齐，**没解决「整段一条」的设计错误**，不能当字幕的最终实现。
