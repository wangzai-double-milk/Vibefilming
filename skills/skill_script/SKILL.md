# Skill · 剧本创作

## 职责

把 brief、灵感、现成稿或已确认拆镜写成可拍的 `script.md`。

剧本只写：

- 谁在什么处境中要完成什么。
- 发生了什么动作、变化和结果。
- 逐字对白、旁白、口播和声音叙事。
- 关键道具与必须持续的状态。

镜头景别、机位、运镜、UI 版式、故事板和生成设置不属于剧本。

## 通用写法

- 开场尽快建立冲突、欲望、危机或结果反差。
- 每一段都推进主线，不堆并列的漂亮场景。
- 台词必须逐字可说，符合人物身份和当下情绪，不写“争吵几句”这类概述。
- 抽象心理改成可见动作或可听语言。
- 重要状态变化写清触发、过程和持续结果。
- 现成稿也要先检查结构、因果、台词密度和事实边界。

## 游戏内容

- **剧情前贴**：写清困境或欲望、选择或反转，以及它如何承接游戏内容。
- **固定逻辑换皮**：保留人物职能、事件因果和反转顺序，只改用户授权的表现内容。
- **玩法转绘**：保留操作预备、交互或发射、命中或反馈、奖励或消耗、升级或下一挑战的顺序。

不要把自动行为写成玩家点击，不要重复领奖、跳过投入或把中段状态提前到开场。建筑建成、升级完成和昼夜变化一旦发生，应持续到有依据的下一次变化。数量可以因击败、合并、生产和建造合理增减。

纯玩法可以没有人物小传和口播，但必须能从操作与反馈看懂目标和结果。

## 电商内容

使用最短可信链路：

`钩子 → 产品身份 → 痛点或欲望 → 使用或证明 → 结果 → 行动`

- 前三秒尽快建立产品或结果。
- 每段至少推进产品、痛点、证明或行动之一。
- 卖点放进真实使用情境，用动作和结果证明，不只喊口号。
- 产品功效、价格、权益、销量、资质和用户证言只使用确认材料。
- 口播按自然语速写，不能靠慢读塞入时长。

## 剧情与人物

剧情型内容为主要角色写稳定的身份、外貌记忆点、目标、恐惧和关系。短片不必机械套三幕，但必须有起因、升级和落点。人物反应应来自具体触发，不直接跳到哭、笑或崩溃。

## 口播覆盖与情绪可执行性

- 用户要求口播时，在正式剧本逐句列出说话人、逐字台词、信息职责、情绪起点与变化、
  预计起止时间。钩子、核心说明与行动句不得只写成字幕；纯玩法无口播要求时不补讲解。
- 用自然中文语速粗估可说性，通常每秒约3–5字，情绪停顿和重音另留时间；这只是排时
  估算，真实录音/生成音频才是证据。超载优先减少重复句，关键事实和用户原文不擅删。
- 对照需求登记必须说出的句子；明确目标是逐句覆盖全部必说内容，不能用“有音轨”
  或“字幕出现了”代替口播覆盖。保留原音轨任务继承原声，不能悄悄写新台词。
- 每次情绪变化来自具体事件，并给出至少两个能看见的反应：视线转向、眉眼张力、
  嘴角变化、身体重心或手势。配对应声线、重音与呼吸，避免全片同一笑脸、无触发大哭
  或仅用“激动、感染力强”概述。
- 高节奏脚本尽早给出事件，删等待和重复解释，保留起势、接触、反馈与结果；
  不靠快读长句或删除因果让视频显得快。

## 参考改编的变更合同

先把改编范围写成三个互斥集合：`允许改变 / 必须保持 / 因果适配闭包`。适配项逐条说明“新条件 → 失效的原假设 → 最小动作或状态变化 → 仍锁定内容”；没有这条因果证据的变化回到保持集合。

- 只换角色：只改指定人物身份与外观，骨架、握持、遮挡和服装随动可按新体型局部适配；背景、玩法、人物目标、事件和节奏不变。
- 只换玩法：重写完成新规则所需的输入、动作、接触和视觉反馈；人物身份、背景身份、镜头职责和节奏落点不变。UI、字幕、数字、CTA 与声音只有用户明确点名时才可改，不能以“玩法相关”或因果闭包自动授权。
- 换环境：纯视觉换景不改人物动作；若新环境明确改变温度、阻力、风力、重力或通行条件，才最小改动保暖层、步态/发力、足迹、环境反应和声音，不改人物身份、目标、关键事件与结果。
- 不同版本均从同一母片的事实稿独立派生，不把某个裂变版本的改动继承给另一个版本。

## 参考视频改编

- 原位编辑是复刻默认：只把用户点名的主变量和已证明的因果适配写入替换表，其他原事件、人物动机、动作顺序、接触、数量、字幕与声音照原片保留。“切鱼”仍是切鱼，不抽象成“破开硬物”后改为砸陨石。
- 结构重建：用户明确不用视频编辑时，把拆镜事实整理成可独立生成的逐镜保留稿。必须保留具体动作拓扑、对象数量、接触、结果、字幕和剧情，例如“刀切冻鱼”仍写刀切冻鱼、“两物合一”仍是两物合一；只改授权变量，不借重生成改故事。
- 生成式重制只在用户明确授权改剧情或自由创作时采用；按实际获准范围重建因果，未获准的人物、场景、动作和文字仍保留。多对象替换或模型重新出视频均不构成改剧情授权。
- 拆镜草稿只能作为依据，正式剧本必须重新整理并落盘。
- 来源不一致时停止定稿，指出具体冲突；不在剧本里维护拆镜文件的同步状态。

## 生成式重制

只有用户明确要求全新剧情时，才按下述步骤创作全新 `script.md`。原位编辑与结构重建都从拆镜事实整理“保留稿＋替换清单”，后者额外写清每镜可生成的状态前、动作、接触、反馈和状态后；不套本节重新发明人物动机、台词和结局。

先建立复刻元素映射：

| 来源元素 | 叙事功能 | 新片表达 | 处理 |
|---|---|---|---|
| 原片的具体钩子或动作 | 它为什么抓人、推进什么 | 新设定下承担同一功能的新事件 | 原样保留 / 功能重写 / 放弃 |

然后从头完成：

1. 用一句话写清新主线、主角目标、阻力和结局。
2. 重新建立 `状态前 → 触发 → 行动 → 接触 → 反馈 → 状态后 → 下一目标`，不沿用与新前提冲突的旧动作。
3. 为每个角色重写动机和反应。敌对变友善后，踢击、格挡、逃跑、受击和伤害反馈必须改成试探、靠近、接触、合作或庆祝。
4. 重写全部剧情字幕、对白、旁白和事件音效；只有品牌、免责声明及与剧情无关的固定信息可以明确保留。
5. 复用来源节奏时保留的是事件落点、切镜密度、反馈间隔和情绪曲线，不是原角色必须重复原动作。
6. 前 `1–2 秒`出现核心事件；通过压缩等待提高节奏，但不能跳过接触、反馈或状态结果。

正式剧本必须能脱离原片独立讲通。读者只看 `script.md` 就能回答“为什么行动、如何接触、发生什么反馈、下一步是什么”，且不会看到任何为旧剧情服务的残留动作。

## 创作经验

写每一段前先回答三个问题：

1. 观众此刻知道什么。
2. 角色或玩家接下来做什么。
3. 这个动作带来了什么新结果。

如果删除一段后主线、证据和情绪都不受影响，这段通常应该删除或合并。

短片里的升级不能只表现为更亮、更大或粒子更多，必须改变能力、资源、环境或下一步选择。剧情前贴也不能只负责吸睛，结尾的困境或欲望要能被游戏内容接住。

口播优先写短句和自然停顿。关键信息不要全部压在最后一秒；角色说到产品、目标或危险时，脚本中应同时安排相应动作或结果。

## 常见 bad case

- 为了节奏压缩跳过投入，结果建筑或奖励凭空出现。
- 把自动战斗写成玩家连续点击，改变了玩法事实。
- 只换角色名字，原人物动机和新世界观并不匹配。
- 口播解释了全部内容，但画面动作本身没有因果。
- 前贴制造的危机和后续玩法毫无关系。
- 台词句句完整工整，所有角色听起来像同一个人。
- 整体重制仍直接使用来源拆镜稿，只替换角色名、背景名或商品名。
- 新设定已经改变敌我或目标，剧本却继续保留旧攻击、躲避、受击、逃跑和旧字幕。
- 声称复刻节奏，实际只是复制原事件；或为了改剧情把高频反馈和前三秒钩子一起丢掉。

## 自审与交付

交付前检查：

- 主线能否一句话说清。
- 每段是否有因果和职责。
- 台词是否逐字、自然且能在计划时长内说完。
- 游戏操作与资源变化是否成立。
- 商业事实是否有来源。
- 是否混入了镜头设计或工具参数。
- 生成式重制是否有复刻元素映射、全新主线和完整新因果，而不是来源剧情的换词版。
- 所有旧动作、字幕和声音是否都已按新前提重新判定，未授权残留为零。

只输出定稿剧本和仍缺的事实，不写执行模式、审批状态或下一阶段内部字段。
