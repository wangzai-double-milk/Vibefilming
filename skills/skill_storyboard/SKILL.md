# Skill · 动作故事板

## 职责

把已确认的 `director_plan`、来源动作证据和登记资产，转成视频模型可直接参考的低保真动作草图。

故事板只回答：

1. 这几秒先发生什么、再发生什么。
2. 人物、物体和摄影机分别往哪里移动。
3. 关键接触、受力、反馈和最终稳定状态在哪里。

不重写剧情，不新增资产，不决定成片切几刀，不替代角色卡、场景图、blocking 图或整场 route map。

## 输入门禁

生成前必须具备：

- 当前逻辑视频单元的时长、动作链、镜头职责和首尾状态。
- 本单元实际使用的人物、场景、道具终版参考。
- 复刻任务的来源视频片段或从该片段提取的动作证据帧。
- `允许改变 / 必须保持 / 因果适配闭包`。

缺动作起势、接触或结果时先回计划补齐，不用故事板替上游猜动作。

## 每个逻辑视频单元一张

故事板按最终一次 Seedance 逻辑生成单元制作，不按整片统一画一张，也不按故事板格数拆视频调用。

根据动作密度自适应面板数：

- `2–4 秒`：3–4 格。
- `4–8 秒`：4–6 格。
- `8–15 秒`：6–9 格。
- capability 允许的长单元：7–9 格稀疏关键动作板，必须覆盖首态、主要触发/接触/
  反馈和末态，不按秒平均采样。若超过 9 个不可合并的关键状态才能讲清，把阻塞写回
  计划产物，由计划职责按机位或动作因果拆生成单元；本 Skill 不自行拆调用。

优先使用 `1×3`、`2×2`、`2×3` 或 `3×3` 的单张组合图。不得为了凑九格重复姿态、制造空格或虚构事件。

## 视觉形态

使用清楚、低成本、可读的规划草图：

- 白色或浅灰纸面，黑色铅笔线、马克笔线或简笔人物。
- 人物用稳定轮廓和少量身份色块区分，不追求脸部、材质和成片光影。
- 场景只保留动作理解所需的地面、门、平台、怪物轮廓和固定地标。
- 每格标面板序号和相对时间，例如 `1 / t=0.0s`、`2 / t=0.6s`。
- 文字说明尽量短；复杂语义写入同名 JSON，不依赖模型生成长段文字。

禁止 `photorealistic`、`cinematic still`、精细上色、电影级写实、成片质感和装饰性概念图。故事板画得像漂亮关键帧即不合格。

## 轨迹符号

一张图内固定使用同一套符号：

- **红色实线箭头**：人物或主要物体的画内运动路径。
- **橙色弧形箭头**：身体、武器、物体的旋转或翻滚。
- **蓝色箭头**：摄影机推、拉、摇、移或跟随方向。
- **黄色星形或十字标记**：接触点、命中点、抓取点或落脚点。
- **红色虚线箭头**：受力、击退、反作用或反馈方向。
- **空心圆 / 实心圆**：动作起点 / 终点。

箭头必须有起点和终点，方向与左右肢体、运动重心和最终落点一致。不得只画一个模糊箭头写“快速移动”。

## 动作链

关键动作至少覆盖：

`初始姿态 → 触发/起势 → 主运动路径 → 接触/命中 → 反馈/反作用 → 落点与稳定状态`

按任务补充：

- 飞踢、挥砍、射击：画清左右肢、武器或脚的弧线、真实接触点和受击方向。
- 推、拉、抓、抱、撑：画清双方接触面、手脚位置、受力方向和持续承重姿态。
- 跌落、翻滚、追逐：画清重心、旋转方向、经过位置和最终朝向。
- 收集、合并、建造、升级：画清输入对象、移动路径、交互点、反馈和不可回退的结果状态。
- UI/资源变化：只用简短规划标记说明触发关系；最终逐字内容仍以计划为准。

高节奏不等于删掉接触。压缩等待和空动作，保留起势、接触、反馈和结果。

## 局部轨迹与整场路线

故事板可以画本生成单元内、当前画面中的局部动作轨迹，例如飞踢弧线、人物转身、物体飞出或镜头跟摇。

人物穿越长走廊、横跨地图、追逐绕障碍物等整场空间路线，仍由独立 scene route map 锁定。故事板引用该路线的当前局部，不得另画一条冲突路线。

## 单变量复刻

- `edit_in_place`：来源视频负责动作与事件。故事板临摹来源动作拓扑和时间落点，只把授权变量及已登记的最小物理适配画进去。
- `structural_remake`：使用来源动作前/后状态帧和拆镜测量重建动作拓扑；图中标明哪些轨迹是近似，不宣称逐帧一致。
- `generative_remake`：新剧本和新计划负责动作；来源视频只提供已登记的节奏、构图或动作类型参考。

只换角色时锁背景、其他人物、怪物、玩法和接触点。只换环境时锁人物身份和事件；真实环境条件变化只画因果闭包内的步态、服装、足迹或受力适配。只换玩法时锁人物与背景身份，重画完整的新操作到反馈闭环。

## 产物

每个生成单元至少落盘：

- `shots/storyboard_<unit_id>_v1.png`
- `shots/storyboard_<unit_id>_v1.json`

JSON 至少记录：

- `contract: vibefilming.action-storyboard/v1`。
- `unit_id`、`duration_s`、`source_range`。
- `panel_count`、每格 `time_s`、可见状态和动作。
- `subject_path`、`camera_path`、`contact_points`、`feedback`、`end_state`。
- `allow_change`、`must_keep`、`causal_adaptations`。
- 真实使用的角色、场景、道具和来源动作参考。
- `request_binding`：计划传入视频请求的故事板图片引用、逐格动作翻译职责和禁止继承项。

图像用 `category=shot` 生成。已登记的人物、场景或道具参与画面时，必须作为真实 `reference_images` 传入；复刻动作还必须使用来源片段证据，不能只靠文字画。

## 下游使用

视频生成时，故事板图片必须作为本单元真实参考输入，并在生成要求中逐格翻译动作语义：

- 说明每格对应哪个时间点和动作阶段。
- 说明箭头分别代表主体、物体、受力或摄影机运动。
- 明确不继承线稿画风、弱色彩、面板边框、箭头、编号、时间标签和说明字。
- 人物外观仍由角色卡锁定，场景结构仍由场景参考锁定，精确长距离路线仍由 route map 锁定。
- 只要本单元强制绑定故事板，就不能使用与 `reference_images` 互斥的严格 `first_frame/last_frame` 模式；同一长镜头改用完整视频 `extend`，同场景新段把边界帧与故事板一起作为普通参考软锚定。不得为使用严格首帧而删掉动作故事板。

不得只写“参考故事板”四个字。

## 放行检查

故事板进入视频生成前必须满足：

- 面板覆盖本单元完整时长，首尾状态与计划一致。
- 起势、路径、接触、反馈、落点没有缺项。
- 箭头颜色和语义统一，左右方向和受力关系不矛盾。
- 没有新增未登记人物、道具、场景、字幕或玩法状态。
- 关键动作不是一张静态姿势配一个模糊箭头。
- 草图风格与成片风格职责分离。
- 图片和 JSON 均真实存在，且视频请求会实际绑定该图片。

失败时只修故事板中的错误面板或轨迹，不改写已经确认的剧本和镜头计划。

提交后把实际请求中的故事板引用、请求或任务 ID、首次/修复尝试号写回
`generation_units.json`。只有文件真实作为参考输入且 prompt 已逐格翻译动作，才算
绑定成功；仅生成图片、写文件名或口头声称“已参考”都不构成证据。
