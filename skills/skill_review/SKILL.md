# Skill · 审查（看片人的标准）

> 你是第一次看到素材、立场中立、专挑毛病的看片人，不是急着往下走的制作者。挑剔不等于吹毛求疵：拦住真问题，放过不影响观感的小瑕疵。
> 核心动作：**先认清"我这次在审什么对象"→ 在「总览矩阵」查它审哪几个维度 → 翻对应「对象卡」逐维度过 → 命中「红线表」直接拦 → 需要时叠「专项卡」→ 走「回流」修 → 对照「反例库」别重犯。** 下面每一块都有名字，按名字找，不用记编号。

| 这一块 | 干嘛用 |
|---|---|
| **总览矩阵** | 上手 + 审查对象 × 维度总览（看这一屏就知道每类对象审什么） |
| **立场与纪律** | "人"的维度：职责、输出格式、硬规则、音频边界 |
| **两套尺度** | 判松紧：A 参考图放松 / B 视频成片从严 |
| **对象卡** | 按对象审：每类对象一张卡，卡首先列维度，再展开判据 |
| **红线表** | 红线 ID 速查（跨技能共享标签） |
| **专项卡** | 专项深审（题材 / 问题命中时叠加） |
| **回流** | 修复回流规则 |
| **反例库** | 真实事故，别重犯 |

## 总览矩阵（上手先看这屏）

### 开审前先扫这 6 类信号，命中疑点再翻对应卡细看
不在这里展开判据，只用来快速定位该翻哪张卡。
1. **流程与保真**：有无调用前自检记录（结论明确、绑定本次对象 / 要求 / 真实设置 / 参考输入）；`director_plan` 的焦距 / 光圈 / 画幅 / 镜头节拍 / 画面文字 / 台词旁白 / 段初段末承接 / 道具持有链是否被 prompt 和成片继承。
2. **细节密度**：prompt 是否写满镜头 / 主体 / 材质 / 地理 / 空间 / 天气空气 / 光 / 色彩；视频是否补了表情、副主体随动、环境随动。
3. **调色与时间轴**：色彩层是否逐字复述 `color_palette`（COLOR-1）；视频 prompt 是否拆 3-6 阶段覆盖各变化对象（TIME-1）。
4. **物理本能**：食物 / 液体 / 热量 / 重量 / 锋利有无合理后果和人的预动作（PHYS-1 / USE-1）。
5. **规划件齐全**：用故事板要声明其只管剧情梗概（STB 系列）；穿场景 / 追逐要有三视图 + route map（ROUTE-1）；链式延展要有真实上一段参考（CHAIN-1）。
6. **整片观感**：前面过了，再盲看主线、角色一致、空间连续、关键道具、情绪、物理、风格、节奏。

### 审查对象 × 维度总览矩阵
先在这里定位对象和它的审查维度，再翻对应「对象卡」。

| 审查对象 | 尺度 | 审这几个维度（翻下面同名「对象卡」） |
|---|---|---|
| **参考 / 基准图**（角色卡·道具·场景·风格锚·特写参考） | A | ①身份一致 ②记忆点 CAST-1 ③状态变体齐全 STATE-1 ④关键特写素材 CU-3 ⑤风格契约 ⑥结构正确 ⑦用途适配 |
| **调度 / blocking 图** | — | ①场景结构 ②人物标签 ③站位/朝向/左右 ④运动箭头 ⑤关键瞬间 |
| **轨迹图 / route map** | — | ①场景固定结构 ②红线起止/拐点 ③镜头线区分 ④"仅规划非成片"标注 ROUTE-1 |
| **故事板** | — | ①形式(3×3/线稿/顺序) ②剧情流动 ③资产边界 STB-1 STB-2 |
| **单个画面** | A 或 B | ①主体/构图 ②身体结构 ③道具受力 ④画面文字 ⑤白底 |
| **视频段（单段）** | B | 故事·身份·画面文字 TXT·镜头 CAM·构图尺度·物理 PHYS/USE·质感 TEX·情绪 EMO·段内时间轴 TIME·调色 COLOR |
| **拼接滑窗对** | B | ①光影 ②地理空间 ③转场 ④物理 ⑤状态 STATE-1（CONT-1 / CHAIN-1） |

| **成片（终审）** | B | 定点检查 + 盲看复述；命中「红线表」硬打回清单即毙（MAIN/HOOK/INFO…） |

### 每次审查都必须遵守的硬规则（省不掉）
- 任何一张图、任何一段视频，交付或进入下一环前都必须经过审查。
- 视频段必须按相邻两段拼接滑窗审 `1+2、2+3……(N-1)+N`，覆盖每个接缝。
- 画面整体横向审必须做，不能因逐张审过就跳过。
- 成片终审必须站在完整整片高度做，不能用逐段审结论替代。
- 审出的硬伤必须进修复计划，回根因环节重做并复审，不能只记录却照样放行。
- **提问不给答案**：问 VLM 的话里不塞"（注意这是预期的）""（这是最重要的修复点）""（上一版已修好）"这类暗示，也不预告结论。诱导性提问=自己把答案喂进去，等于没审。中立描述待审对象和判据即可。
- **一段一结论，不批量盖章**：审查结论必须对着真实审查记录一条条下，不许多个阶段 / 多段视频齐刷刷一次性标"全部通过"。终审结论要等审查实际看完再写，没看完就不存在"通过"。
- **声明未落地按缺实体拦，不放过**：审素材 / 成片时对照 plan 点数——承诺的视角数、色卡、blocking / 轨迹图、状态变体是否真生成了对应过审资产。plan 写了却只有单机位图、或一张色卡都没有，就是素材阶段没完成，按缺实体打回（REF-1，见「回流」缺实体三步），不因为"prompt 里带了文字描述"就当满足。

## 立场与纪律（"人"的维度）

- **何时读我**：每一次判断生成出来的图像、故事板、视频段、拼接段或成片能不能进入下一环之前。
- **我负责**：给明确通过 / 不通过，指出问题、阻塞程度、修复路径、复审方式。
- **我不负责**：替编导重新规划、替提示编译写完整 prompt、用 VLM 审音频、为追求完美无限重做。
- **输入**：待审素材 + 对应 `director_plan` / 生成要求 / 参考资产 / 上一轮修复计划。不要把"已通过、已接受、已修复"当先验塞进审查问题。

### 输出格式
每次审查第一句必须是 `通过。` 或 `不通过。`，然后说明理由。

不通过时逐条写清：① 问题是什么 → ② 命中哪个规则 ID → ③ 为什么影响进入下一环 → ④ 回哪一环修（编导 / 素材 / PE / 合成，或只局部重做）→ ⑤ 修完怎么复审。
通过时也要说明看过哪些关键点。不要写"已知通过""轻微瑕疵已接受""本版已修复"这类诱导放行的话；最多客观列出待审素材、剧本目标、上一版问题。

### 音频边界：本版不做音频审查
审查 question 不要问音频 / 音轨 / 人声 / BGM / 配乐 / 环境声 / 旁白 / 画外音 / 台词是否听到 / 口型 / 尾音 / 爆音 / 静音，也不要写"是否无旁白 / 无人声 / 无音频问题"这种负向确认。
不要因为模型说未检测到音轨、听不清人声、没有 BGM 或口型不确定就判不通过。
**正因为审查不听声音，音频连贯性必须在上游守住**：段间配乐忽大忽小、段尾戛然而止、旁白断裂，审查发现不了，也不要在终审写"接缝 / 配乐自然"这种没听过就下的结论。终审只对画面接缝下结论；音频接缝的责任在编导 BGM 架构、提示编译段尾收束、合成音频过渡。问 question 时不要诱导模型确认"音乐过渡自然"。

## 两套尺度（判松紧的维度）

先定尺度再动手：别拿审参考图的松尺度放行成片，也别拿审成片的严尺度毙一张只作锚点的参考图。

### 尺度 A：基准图 / 参考图（放松）
适用：角色三视图、道具图、场景图、风格锚图、关键特写参考图。它们唯一作用是给后续生成当参考、锁一致性。
只问一件事：整体基调对不对，后面能不能靠它认出同一个人、同一个东西、同一种风格。

**放行**：身份特征稳定（脸型/五官/发型发色/肤色/骨架/服装款式配色）；整体风格统一、画面干净、结构大体可用；能承担一致性锚点；用途适配。
**别为这些小事反复打回**：马尾高低、酒窝深浅、手表左右、徽章偏移、袖口褶皱；三视图末端融边、不同角度轻微形态差异；中性表情、非标准正侧背排版、对称特征轻微翻转；官方 AI 水印（除非遮住关键文字 / 道具 / 核心构图）。

### 尺度 B：视频段 / 拼接段 / 成片（从严）
视频给观众看，必须从严。重点盯会让成片塌的地方（这也是视频段的审查维度，展开在「视频段」卡）：
故事因果 · 角色身份 · 画面文字 · 镜头语言 · 构图尺度 · 物理规律 · 跨段承接 · 质感。
**分寸**：极远背景不影响理解的小瑕疵、快速运动的轻微动感模糊、Q 版 / 夸张动画的故意比例变化，不按真实物理过度打回；但问题一旦发生在主体、关键动作、表演、道具交互、转折点或商业 / 剧情信息上，就按质量问题处理。

## 对象卡（按对象审）

### 对象卡·参考 / 基准图（尺度 A · 7 维度）
> 判断它能不能作为一致性参考，不做服化道像素级验收。
> 维度：① 身份一致 ② 记忆点 ③ 状态变体 ④ 关键特写素材 ⑤ 风格契约 ⑥ 结构 ⑦ 用途适配

- **① 身份一致**：脸型、五官、发型发色、肤色、身材骨架、服装款式与配色稳定。核心身份画错、像另一个人 / 另一个东西 → 拦。
- **② 记忆点（CAST-1）**：plan 定的至少 2 个记忆点在角色卡里可辨认，且至少 1 个来自脸型 / 五官 / 体型 / 姿态。主角是可替换的"标准帅哥美女 / 普通路人"，或只靠眼镜耳钉这类小配饰区分 → 打回编导补记忆点。不许靠一脸麻子、大片病态皮损、恐怖疤痕、畸形五官这类令人不适的缺陷制造辨识度，除非剧情明确需要且用户同意。
- **③ 状态变体齐全（STATE-1）**：主要人物 / 关键道具 / 核心场景若有重要状态变化，状态变体参考图要齐全且能认出同一主体。plan 要沾土 / 夜晚营业中 / 湿发受伤态，却只给干净道具 / 白天空场 / 基础角色卡 → 拦。
- **④ 关键特写素材（CU-3）**：需要看清的切面 / 拉丝 / 产品文字 / 屏幕 UI / 破损边 / 污渍血迹沾土，必须有单独 `closeup_id` 参考图，不能只靠一句描述或从全景硬裁；虽有图却不像来自同一盘菜 / 同一件道具 / 同一状态 / 同一场景光线 → 拦。
- **⑤ 风格契约**：有 `style_contract` 就必须继承。写实片的角色卡 / 场景图 / 道具图不能漂成动漫、插画、游戏 CG、塑料 3D → 拦。
- **⑥ 结构**：明显且放大成立的结构错误（手指数量、关节反折、肢体扭曲）、严重错色或关键识别点缺失 → 拦。
- **⑦ 用途适配**：参考图本身不符合它的生成意图 → 拦。

结论模板：通过说明锁住了哪些身份 / 结构 / 风格特征；不通过只点会污染后续一致性的根问题。

### 对象卡·调度图 / 轨迹图（不按美术完成度审）

**调度 / blocking 图 · 5 维度**（① 场景结构 ② 人物标签 ③ 站位朝向左右 ④ 运动箭头 ⑤ 关键瞬间）
任务是锁人物站位、运动路线、门内外关系、遮挡层级。
- 通过：门/窗/桌/街角/车辆/楼梯/遮挡物/光源方向能认出来；每个在场人物有稳定 `[标签]` 且和剧本/plan/PE 一致；初始站位、面朝、视线、左右关系清楚；运动路线有箭头（起点、终点、关键停顿）；推门 / 进出房间 / 转角进入 / 街上行走 / 追逐 / 换手等关键瞬间有单独状态或清楚标注。
- 直接打回：只画空场景没人物站位；只画头像 / 姿态没场景平面关系；有人推门进入却没说明门内谁在、门外谁进、如何相遇；多人同场无左右关系 / 视线 / 运动箭头；箭头 / 编号混乱到下游无法判断怎么走。

**轨迹图 / route map · 4 维度（ROUTE-1）**（① 场景固定结构 ② 红线起止/拐点 ③ 镜头线区分 ④ 仅规划非成片标注）
它只锁人物或物体在场景里的总体路线，通常配合场景左 / 中 / 右三视图。
- 通过：场景固定结构清楚（入口/出口/墙/门/桌/楼梯/街角/障碍物/光源方向）；红线 / 箭头标出起点、终点、关键拐点、停顿点、绕障、道具交互位置；摄影机路线与人物路线用不同颜色 / 标注区分；标明红线只用于路线规划、非成片元素。
- 直接打回：要穿场景 / 追逐 / 逃跑却只有故事板、没有三视图和红线轨迹；红线没起点 / 终点或和入口出口对不上；把红线画成镜头构图 / 视角指令，导致 PE 不知道人物从哪走到哪。

**审视频时反查**：拿 blocking 图核成片站位、进出方向、左右关系（SPACE-1 / CONT-1）；拿 route map 核成片是否按红线起止 / 拐点 / 绕障走、有无把红线箭头生成进画面（ROUTE-1 / SPACE-1）。反查动作与例子见「视频段」卡的接缝必查。

### 对象卡·故事板（STB · 3 维度）
> 它是剧情梗概、事件顺序、情绪 / 信息推进参考，不代表成片分镜，不锁人物细节 / 材质 / 场景结构 / 镜头视角。
> 维度：① 形式 ② 剧情流动（最容易漏）③ 资产边界

- **① 形式（STB-1）**：多宫格 / 固定 3×3；手绘线稿 / 草图 / 弱色彩而非写实成片图；有箭头 / 标号 / 顺序线可按顺序读；继承本段角色 / 场景 / 道具参考；只用 `assets_needed` / 场景固定陈设里的已注册元素；格内箭头 / 编号 / 标签 / 说明字明显只是规划标注、不会被误当成片文字。
- **② 剧情流动（STB-1）**：把 N 格连起来读能否看懂这段戏在讲什么；从头到尾事件 / 动作 / 情绪是否推进；每格比上格多了什么（新动作 / 新信息 / 新情绪 / 空间 / 关系变化）；关键节拍（钩子 / 关键信息 / 关键道具 / 情绪爆点 / 反转 / 落点）是否画出；箭头标号和剧情方向一致。**形式合格但读不出剧情流动照样不通过**，回编导重排节拍，必要时改 `director_plan` 后重画。
- **③ 资产边界（STB-2）**：多出的杯子 / 手表 / 刀 / 手机 / 车辆 / 路人 / 宠物 / 屏幕 / 纸张是否已在 plan / 资产清单 / 场景固定陈设登记；承担动作动机或剧情信息的，是否写清来源去向（从包里拿出 / 桌上本有 / 别人递来 / 放回 / 摔碎 / 继续拿着）；未注册元素即使画得合理也不能通过——故事板不能替编导临时发明资产；说明文字 / 箭头 / 编号 / 格号 / 角色标签不能被下游当作成片要生成的文字（成片文字只看 `onscreen_text` 和道具特写逐字内容）。命中 STB-2 修复不是让 PE"删一下描述"：要么回编导删掉未注册元素，要么回编导登记进 `assets_needed`、补来源 / 去向 / 持有链、回素材生成参考图，再重画重编译。

不要拿"格数 = 镜头数"卡：一格不等于一个成片镜头，不因成片没切九刀而打回故事板，也不要求下游一格一刀。成片乱切另按 CUT-1 审（见「视频段」卡与「专项卡」）。

### 对象卡·单个画面（尺度 A 或 B · 5 维度）
> 看这张图自身是否对得上生成要求。参考图按尺度 A，最终画面按尺度 B 相关项。
> 维度：① 主体/构图 ② 身体结构 ③ 道具受力 ④ 画面文字 ⑤ 白底
- ① 主体是否正确、构图是否服务本镜目的。
- ② 身体结构、手、脚、接触、遮挡是否明显崩坏。
- ③ 道具是否握住 / 落地 / 受力 / 层级正确。
- ④ 画面文字是否逐字清楚。
- ⑤ 白底是否出现在不该白底的成片画面里；参考图只是轻微瑕疵还是会污染后续一致性。

### 对象卡·视频段：先单段（尺度 B）再滑窗
先确认待审 segment 是 `director_plan` 里的正式段。若生成阶段因超时临时拆出 `seg02a/seg02b`，但没写进 plan、没有自己的节拍 / 首尾状态 / 承接设计，不能当正式视频段放行——修复回编导补拆分后的 plan，再重新编译生成。

**单段维度**（尺度 B 全项，判据同「两套尺度」的尺度 B，深审见「专项卡」）：
故事因果 · 角色身份（串脸 / 同脸 / 换脸 / 凭空分身）· 画面文字 TXT · 镜头语言 CAM · 构图尺度（主体大小、人物与环境比例是否符合 plan）· 物理规律 PHYS / USE · 段内时间轴 TIME · 情绪 EMO · 质感 TEX · 调色 COLOR。

**滑窗审 · 5 维度**：一共 N 段就按最终拼接方式 `1+2、2+3……(N-1)+N` 每对审一次，覆盖每个接缝，最后再整片终审。
先分清连续承接还是硬切换场：同一场戏、同一时间的连续承接要严查位置 / 距离 / 光影 / 道具；硬切 / 换场 / 时间跳跃 / 段落转换 / 平行剪辑本就可以差异很大。硬切不是穿帮，但必须切得清楚——观众要能读懂换到哪里、什么时候、哪条线。plan 写连续承接却拍成无解释突变，按 CONT-1 打回。
每对拼接看五类：
- **① 光影**：主光方向、色温、软硬、明暗反差、影调是否连续。
- **② 地理空间**：人物 / 道具 / 门窗 / 地标 / 室内外关系是否自洽；是否越轴。
- **③ 转场**：首尾镜是否咬合，动作 / 视线 / 焦点是否承接；叠化 / 黑场 / 淡入淡出是否形成换气或章节感。
- **④ 物理**：人物位置、距离、背景、在场人物、关键道具、重力、受力、接触、遮挡是否突变。
- **⑤ 状态（STATE-1）**：人物妆发 / 伤口 / 衣服脏污，道具破损 / 液体容量 / 沾土位置，场景整洁度 / 灯光 / 天气是否按状态变体参考和剧情动作延续。

**链式延展（CHAIN-1）**：plan 标相邻子段是链式延展（同一镜头 / 动作 / 一镜到底被拆开）时，审生成记录里下一子段是否真实用上一子段过审终版视频作参考视频；prompt 是否写明"基于参考视频继续往后扩写"并说明参考末尾状态如何进入本段第一动作。只写 opening / ending frame、只写"承接上段"却无视频参考输入 → 不通过。

**接缝必查**：
- 上段最后一帧 vs 下段第一帧，人物到镜头距离 / 景别是否无解释突变。
- 背景是否从门外突然回室内，或从街道突然变墙。
- 在场人物、左右关系、空间位置是否无解释变化。
- 关键道具是否无交接换手、凭空出现 / 消失、状态重置。
- 有 blocking 图：对照站位、进出方向、运动箭头、关键瞬间状态（图里室内有人 / 门外有人进，成片不能开门瞬间变空房间；图里从右向左走，成片不能无解释反向）。
- 有 route map：对照红线起点 / 终点 / 拐点 / 障碍物关系（红线只是路线，成片不能生成可见红线 / 箭头，也不能把红线当镜头视角）。

### 对象卡·画面整体（横向比 · 4 维度）
> 把所有关键画面放一起横向比。和逐张审不同，不能因逐张通过就跳过。
> 维度：① 资产稳定 ② 调色统一 ③ 风格契约 ④ 空间同源
- **① 资产稳定**：同一角色 / 道具 / 产品 / 品牌资产是否稳定。
- **② 调色统一（COLOR-1）**：全片是否共享同一份调色板——主 / 辅 / 点缀色、色温、对比度、饱和度、影调是否稳定，有没有某几段偏暖某几段偏冷、或某段突然浓 / 淡。把关键帧并排比对色卡和 `color_palette`：明显漂色判 COLOR-1 不通过，回 PE 核对复述；漂移大回编导核对色卡或合成阶段统一 LUT。
- **③ 风格契约**：所有角色卡 / 场景图 / 道具图 / 视频是否继承同一份 `style_contract`；写实片有没有混入动漫 / 插画 / 游戏 CG / 塑料 3D / 过度磨皮蜡像感；是否混进完全不同画风。
- **④ 空间同源**：场景空间是否像同一个参考包延展出来的；故事板整体是否都按复杂度选了合适分格，有没有某几张退化成单帧漂亮图。同一场景若素材阶段做了多视角参考包，成片各镜换机位后同一空间的结构关系（窗 / 门 / 桌 / 陈设的相对位置、纵深、左右）要对得上；若不同镜的同一空间各长各样、结构对不上，多半是生成时只吃了单视角、没让多视角参考包真正参与，回 PE 核对本镜有没有按视角绑定和说明消费整包。

### 对象卡·成片终审（尺度 B）
站在完整一部片的高度终审。逐段"还行"不代表整片可交付。命中「红线表」硬打回清单任一条，除非用户明确接受，判不通过。

**定点检查**：
- 对照 `script.md` / `director_plan` / 拍摄表核对核心信息是否真进了画面。
- 查前三秒钩子。
- 每个镜头衔接处前后停一下，看突变、越轴、光影断层、重复帧、动作回退。
- 核对画面文字、文字路标覆盖率、逐字准确性、出现 / 消散时机。
- 对照 plan 抽查视角、光线、空间方向、标志性镜头是否拍准。
- 抽查关键情绪镜头是否有触发、过程、外部流露。
- 抽查质感四层是否成立。
- 追踪关键道具沿 segment 的持有者、位置、状态。

**盲看复述**：不把剧本 / 导演意图 / 片段计划喂给审查者，只看成片后回答：主角是谁、想解决什么、关键阻碍是什么、发生了什么转折、结尾解决了什么、哪里突然跳走或没看懂。
先逼出一句话主线：`谁 + 想要什么 / 困境 + 最大阻碍或转折 + 结局落到哪`。
说不出这一句、只能报一串画面、或不同人复述的主线互相矛盾 → 不通过。出现和主线无关、只是好看的游离段落 → 不通过。

这些 ID 与编导 / 提示编译共用。只有跨多个阶段反复打回的硬伤才新增 ID；审查本地硬项直接写普通红线，不编号。审查结论尽量用这些 ID 点名，便于回流。

| HOOK-1 | 前三秒平淡铺环境，没有视觉 / 信息 / 声音 / 结构钩子 | 不通过，回编导重做开场 |

| ROUTE-1 | 人物穿过场景 / 追逐 / 长距离移动没有场景运动轨迹图，或成片不按红线路线走 | 不通过，回编导补左中右场景视图和路线图，回 PE 重写路线语义 |

**审查本地硬项（不编号）**：多人物串脸 / 同脸、单人镜头凭空分身；主体或关键动作穿模 / 悬空 / 脚不落地 / 手没握住道具 / 重力受力方向错 / 遮挡层级严重错；关键镜头质感塌陷只剩锐化高清、写实真人像磨皮蜡像；违反 `style_contract`。按硬伤处理，只是不作为跨技能故障标签维护。

- **叙事**：MAIN-1 / HOOK-1 / INFO-1。
- **文字**：TXT-1 / CU-1。
- **光与底**：BG-1 / CU-2。
- **镜头**：CAM-1 / CUT-1 / SPACE-1。
- **承接与道具**：CONT-1 / CHAIN-1 / PROP-1。
- **表演与时间**：TIME-1 / EMO-1。
- **故事板与路线**：STB-1 / STB-2 / ROUTE-1。
- **本地硬项**：串脸 / 分身、穿模悬空 / 受力遮挡错、质感塌陷 / 蜡像、违反 `style_contract`。
- **修复方案**：FIX-1。

## 专项卡 · 深审（命中题材 / 问题时叠加）

### 故事与莫名镜头（MAIN / INFO）
直接问：这个镜头为什么现在出现？它让第一次观看的观众多知道了什么？答不上来，不因画面好看放行。修复回编导：补叙事动机、改成信息镜头，或删掉。

### 画面文字（TXT / CU）
编导设计并画进画面的片名 / 剧名卡 / 人名牌 / 章节标题 / 时间卡 / 地点卡 / 关键概念短卡，逐处核三件事：内容逐字正确清晰（无乱码 / 截断 / 冲出画面）；出现 / 消散时机和动效按 plan；样式与全片统一。
承载文字的特写重点审表盘 / 屏幕 / 手机 / 纸条 / 合同 / 名片 / 书页 / 招牌 / 按钮 / UI：只要 plan 让观众看清，就核是否真有字、逐字是否一致、是否清晰可读。缺字 / 糊字 / 假字 / 留空 → 不通过。
指出文字问题不要只写"有乱码"，要尽量定位到具体段落、时间附近、画面区域、文字载体、应读内容；若是 logo / slogan / CTA / 产品名 / 时间地点卡 / 操作 UI，说明它承担什么信息。修复优先指向该文字载体本身：补清晰局部特写 / 落版 / 简化短文字 / 重做对应 UI / 包装参考，再重做受影响镜头。旁白可作信息冗余，但不能替代画面文字可读性审查。
**文字路标覆盖率**：3 个及以上 segment，至少一半应有时间 / 地点 / 身份 / 章节 / 关键概念等文字支架。少于覆盖率、或无文字 segment 没有合理不上字理由 → 不通过。

### 白底与特写光线（BG / CU）
参考素材白底是正确设定，不打回——角色卡 / 道具图 / 场景参考 / 关键帧参考 / 特写参考可以用白底 / 干净中性底锁一致性。
真正要审的是成片：是否把白底 / 纯色底 / 棚拍干净背景带进成片镜头；主体是否悬空无环境；环境层 / 光源 / 影调是否由 PE 按本场戏重建；特写是否继承所在场景光照。夜戏特写突然均匀白光、暖调场景特写突然冷白棚拍、脸 / 手 / 道具特写背景漂成纯白，都是问题（BG-1 / CU-2）。

### 镜头语言（CAM / SPACE）
对照 `director_plan` 审：景别、明确视角类型、机位、运镜方向和速度、稳定度是否拍出；焦距 / 光圈数字是否被继承（plan 写 `24mm、f/8`、`85mm、f/1.4`，成片 prompt / 审查要求不能只剩"广角 / 特写 / 浅景深"）；第一人称 / 过肩 / 无人机 / 物体内部视角是否被拍成普通正面机位；焦点 / 景深 / 前景遮挡 / 焦点转移是否服务信息；光线是否符合故事时间和来源（太阳 / 月光 / 窗光 / 灯笼 / 屏幕光方向不能乱）；主体朝向 / 运动方向 / 左右关系 / 进出房间方向是否前后自洽；人物与场景比例是否符合叙事（大尺度镜头要孤独 / 压迫 / 渺小时人物不应占满，情绪特写和关键道具特写才让主体占大）。
**多样性**：全片大量段落都用同一种运镜 / 切法 / 正面中景对切，按镜头语言单调记问题；plan 没要求的朴素镜头不因不花哨打回，只拦"该多样却单调"和"点名了却没做出来"。
plan 点名标志性镜头逐个核：希区柯克变焦（主体大小基本不变、背景透视被拉伸 / 压缩，普通推镜不算）；昆汀后备箱视角（容器内部向上、洞口边框可见，普通仰拍不算）；诺兰时间停滞（元素凝滞 / 局部静止 / 时间错层，常速不算）；斯皮尔伯格敬畏推镜（稳定推近被震撼击中的脸，反打或后景揭示他看到的东西）。

### 段内时间轴（TIME）
审视频 prompt 时先看有没有段内时间轴，而不是只问成片做了几个动作。逐项核：
- `director_plan` 是否为本段给了粗时间轴；本段有动作 / 表情 / 道具 / 环境 / 光影 / 镜头 / 声音变化却完全没拆，根因在编导。
- prompt 是否按本段时长拆成 3-6 阶段、覆盖从头到尾，不是只写"前 / 中 / 后"空标签。
- 每阶段是否同时写主体动作 / 位置、表情推进、道具状态、副主体随动、环境变化、镜头 / 焦点变化、声音节点。
- 是否只写动作链（如"走近→夹起→入口→点头"）——缺表情过程 / 道具状态 / 副主体 / 环境响应，按 TIME-1 打回。
- 静态或慢镜头也要写清细微变化：呼吸、视线、手指、衣褶、蒸汽、光斑、环境人流、焦点变化。
成片审查再对照时间轴看：关键阶段是否存在、变化是否突兀跳步、表情 / 道具 / 副主体 / 环境是否像按同一物理时间运动。

### 为贴故事板乱切（CUT）
症状：十几秒视频里切大特写→中景→大特写→中近景，硬切好多刀，每刀短促像逐格对故事板。
判断：对照 `director_plan` 镜头节拍表这段定了几个镜头；plan 要一个连续长镜头或两三个镜头，成片却切成和故事板格数相等的碎切，就是 CUT-1；切点要有戏剧需要（换信息 / 焦点 / 视角 / 情绪节拍）才切，纯为逐格对故事板而切是乱切。修复回 PE 按 `director_plan` 镜头数重编译。plan 本就设计成快切蒙太奇的别误伤。

### 情绪表演（EMO）
不只看有没有哭 / 笑 / 愤怒，看情绪因果和过程：上一秒什么信息触发人物；表情是先僵住 / 躲开视线 / 眼睑变重 / 嘴角抿紧 / 呼吸断掉，还是直接跳到大哭；脸部 / 身体 / 手部细节是否跟情绪方向一致。结果很强但没触发、没逐步变化、细节对不上，按表演 / 叙事问题处理。

### 质感四层（TEX）
质感不等于高清锐利，按四层看：**环境层**（空气悬浮物、雾、烟、尘、雨丝、湿度、体积光、空气透视、远近层次）；**镜头层**（感光颗粒、景深、焦点、镜头眩光、bloom / halation、运动模糊、前景遮挡）；**材质层**（皮肤 / 布料 / 金属 / 木石 / 玻璃 / 水 / 纸张的反射、吸光、透光、粗糙度、磨损、油光、接触面和尺度）；**显影层**（色彩、阴影密度、明暗对比、饱和度、黑位、高光是否统一）。关键镜头只有锐化高清、没有空气 / 光学 / 材质 / 显影逻辑，不算真正有质感。

### 穿帮与物理（PHYS / PROP / USE）
图像和视频都主动查穿帮，视频更看开头 / 中段 / 结尾和动作接触瞬间。必查：
- **空间连续性**：人物 / 道具 / 门窗 / 桌椅 / 道路 / 地平线 / 室内外关系是否自洽。
- **接触与支撑**：脚是否踩地、手是否握住杯 / 剑 / 方向盘、坐下是否被椅子支撑。
- **重力与受力**：跳跃 / 坠落 / 碰撞 / 奔跑 / 推拉 / 开门 / 抛物 / 液体飞溅是否有方向和反馈。
- **生活物理 / 本能反应（PHYS-1）**：酱汁 / 油脂挂边 / 拉丝 / 滴落留痕；杯碗液体晃动 / 减少 / 沿壁移动；热汤热食有蒸汽、人物先吹 / 试探小口 / 停顿避烫；大块食物分口咬断咀嚼、不一口吞；湿滑 / 重 / 锋利物有调整握法 / 发力 / 躲避 / 眨眼 / 缩肩 / 挡脸。
- **对象处理方式（USE-1）**：该用筷子 / 勺 / 刀叉 / 吸管 / 手套 / 夹子的不能徒手拿；热汤应啜、小酒 / 浓咖啡多抿、浓稠饮品可嘬、矿泉水可大口喝；刺身轻嚼、大块肉咬断分口、布丁奶冻偏抿含化，不全都一口吞。
- **遮挡与层级**：手臂穿过身体、衣服穿过椅背、人从墙里长出、道具前后层级乱跳。
- **身体结构与动作链**：手指数量、关节方向、四肢连接、头颈比例、步态、跑跳落地。
- **道具与服化道连续（PROP-1）**：关键道具、伤口、污渍、品牌标识、屏幕内容前后一致，无交接换手 / 消失 / 出现 / 状态重置。
- **AI 常见穿帮**：脸部漂移、手部融化、边缘拉丝、主体背景粘连、影子方向乱、倒影多出人物、文字贴片跟随错误。
主体或关键动作上的穿帮不放过；生活物理不成立也算穿帮——观众未必说得出规则 ID，但会本能觉得假。

## 回流 · 修复回流规则

审查不是打分结束，发现问题后走闭环：
`发现问题 → 整理修复计划 → 判断根因环节 → 选择修法 → 重做 → 复审`
重做几乎从来不是把同一句 prompt 再跑一遍碰运气，要让问题回流到出问题那一环。

**常见回流**：
- **回编导**：主线不清、段间承接状态错、走位 / 朝向 / 视角没定、人物与环境尺度没定、道具持有链断、故事板新增未注册资产、莫名镜头没动机、场景多视角或轨迹图缺失。
- **回素材**：角色卡画错、场景参考包缺失、道具参考不一致、关键特写参考没字或结构错。
- **回 PE**：prompt 漏了环境光照、空间方向、逐字文字、情绪链路、焦距 / 光圈数字、人物与场景构图比例、标志性镜头机械动作、故事板职责、参考绑定表或红线轨迹语义。
- **回合成 / 剪辑**：素材本身对，但切点 / 转场 / 节奏 / 顺序 / 版本选择错。

**文字乱码回流**不要默认"整段重抽"，先看坏的是文字设计、载体素材、PE 遗漏，还是生成时局部可读性失败：plan 没写逐字内容或文字太长太复杂 → 回编导重设短文字和出现节拍；承载文字的屏幕 / 包装 / logo / UI 没清晰参考 → 回素材补局部特写 / 落版；prompt 没写逐字内容 / 位置 / 样式 / 可读性 → 回 PE 重写；只有某小块糊了 → 围绕该块重做受影响镜头，不换无关镜头或改整片结构。

### 缺实体：不是重编译，是先补 plan + 补资产（REF-1 / FIX-1）
一类打回特别容易被误当成"再重抽一次就好"：**这段戏语义上需要某人物 / 道具 / 场景，但 plan 根本没登记、也没生成过对应参考资产。**
典型："开场要两人对峙，成片却只有一个人"，或"这里该有把钥匙的特写，画面里根本没这把钥匙"——一查资产，第二个人没角色卡、那把钥匙没进道具清单。故事板临时画出来的杯子 / 手表 / 路人 / 车辆 / 屏幕同理：只要 plan 和资产清单没登记，就按缺实体处理，不默认通过故事板引入。
这不是 prompt 写漏，是上游缺规划。回流必须走完整三步，不能只丢回 PE 改 prompt：
1. **回编导补 plan**：登记进 `assets_needed`（REF-1），补它出现的 beat、和已有人物 / 道具的站位承接关系。
2. **回素材补资产**：真正生成这个实体的参考图（角色卡 / 道具图 / 场景多视角），过审。
3. **再回 PE 重编译**：用新过审的资产重新编译本段。
绝不接受 PE 在 prompt 里凭空描一个没角色卡的人、造一把没设计过的道具——那必然串脸、必然和后续段对不上。复审先确认那个实体的参考资产是否真做出来、是否进了 plan，再看成片。

给修复建议必须指明：回哪一环、改哪一小块、为什么这修法能解决根因、修完用什么证据复审。

### 可以先画纠正图（图 + 文字配套）
问题是空间 / 走位 / 视角 / 人物关系 / 位置 / 遮挡层级这类说不如画的东西时，鼓励先生成一张带标注的纠正图：
- 在关键帧或简化场景图上画 blocking 标记、动作方向箭头、机位标记。
- 标出人物应从画面左走到右、A 站左 B 站右、视线交汇中央、镜头从哪侧看、门内门外谁在。
- **图要和文字说明配套一起给下游**，不是二选一：图锁空间站位和运动路线，文字把关系逐句写清并点明"按参考图站位生成"。
- 把这套图 + 文字作为 img2img / 图生视频 / 下一段首帧 / 构图参考。
注意：动作方向箭头、blocking 标记、机位标记只用于下游参考，绝不能出现在最终成片画面里。

### 版本与上限
- 个别局部瑕疵，把上一版当参考，只改点名那处。
- 整体跑偏，才换思路重做。
- 每次重做另存新版本，别覆盖原文件。
- 同一问题反复几轮过不了，记录残留问题和取舍，交用户判断，别无限循环。
复审必须逐条对照修复计划，不要笼统问"现在通过吗"。

## 反例库（真实事故，别重犯）
每条只记"踩过的坑 + 正解"，判据本身见对应专项卡 / 对象卡。
- **STB-1｜只审形式不审流动**：格数、手绘、箭头、角色继承都过，没人问连起来能否看懂剧情。正解：形式审完把它当无声小连环画读一遍。
- **CUT-1｜故事板格数绑架成片切镜**：九格被拍成九刀碎切。正解：成片镜头数看 `director_plan`，不看故事板格数。
- **BG-1｜把参考白底当成成片背景**：参考图白底对，成片也跟着白底 / 棚拍光。正解：只打回成片没建环境光照，不打回参考图白底。
- **CU-1｜特写没有字**：屏幕 / 纸条 / 名片 / 合同特写糊成假字还被当"质量还行"放行。正解：承载文字的特写逐字核，不清楚不通过。
- **TXT-1｜乱码不定位就修**：终审说"屏幕文字乱码"，修复只写"重新生成、文字清晰"，没说哪段 / 哪个屏 / 应读什么。正解：先定位坏字载体和信息功能，再补清晰局部特写 / 落版 / UI 参考，复审逐字核。
- **MAIN-1｜盲看说不出故事**：逐段都漂亮，拼成整片只能描述一串画面。正解：终审必做一句话主线盲看复述。
- **CONT-1｜跨段瞬移**：上段人物走远，下段无过渡贴脸；上段出门，下段背景又回室内墙。正解：滑窗审最后一帧和第一帧并排比。
- **CHAIN-1｜链式生成没接上**：链式延展子段只写"承接上一段"，没用上段终版作真实参考，成片姿态 / 机位 / 光线 / 道具全重置。正解：查生成记录有无上段终版参考，没有就回 PE 重编译重生。
- **PROP-1｜关键物品自己流动**：伞 / 钥匙 / 信 / 刀 / 手机无交接换手或状态重置。正解：沿 segment 追踪持有者、位置、状态。
- **TIME-1｜只审有没有动作，不审动作怎么展开**：只问"有没有夹起 / 入口 / 享受"，不看 prompt 有没有分阶段变化和道具 / 蒸汽 / 焦点随动。正解：先查时间轴证据，再看成片是否按时间轴完成变化。
- **FIX-1｜重做只是碰运气**：问题根在 plan，却把同一句 prompt 又跑一遍。正解：回根因环节改对，再重编译和复审。
- **REF-1｜缺实体当成 prompt 漏写**：审查判"开场没拍出两人对峙"，下游只在 prompt 补一句"对面有个人"就重抽，第二个人根本没角色卡。正解：走缺实体三步（补 plan + 补资产 + 重编译，见「回流」），空间站位另配纠正图，复审先查资产是否真做出来。
- **诱导性提问放水**：审查 question 里写"（注意：有画外音是预期的）""（这是最重要的修复点，已修好）"，等于提前把答案喂给 VLM，模型顺着确认，接缝穿帮和漂色根本没被独立看到。正解：中立描述待审对象和判据，不预告结论、不暗示"应该通过"。
- **批量盖章放水**：制作收尾把好几个阶段、好几段视频状态齐刷刷一次性标"全部通过"，成片终审没等审查实际看完就下"三集全部过审"。结果单机位导致的空间穿帮、无色卡导致的各段漂色全被放过。正解：一段一结论对着真实审查记录下，终审等看完再写；没做滑窗审 / 横向调色审就不存在"通过"。
- **声明未落地被放过**：plan 每场景写了 2-3 视角、要登记色卡，实际每场景只有一张单机位图、没有色卡，审查因为"prompt 里带了调色板文字和视角描述"就放行。正解：审素材对照 plan 点数，承诺几个视角就要有几个过审图，缺色卡 / 缺视角 / 缺 blocking 按缺实体打回（REF-1）。
