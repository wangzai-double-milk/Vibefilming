# Skill · 制作审查
## 原则
- 用户直接提供的素材是事实来源，只做技术校验，不做质量审批。
- 只审 Agent 新生成且会影响最终交付的内容。
- 不做滑窗审，不逐素材全量审查，不让视觉模型审音频。
- 第一行必须是 `通过。` 或 `不通过。`
- 不通过时只列阻塞问题，并写清时间、区域、对象、影响、根因和最小修复。
## 最小审查路径
1. 生成前检查文本可执行性与实际 Seedance 请求策略：单次直出、完整视频 `extend`、严格首尾帧或带其他参考的软锚点必须符合计划且互不混传。
2. 新生成的核心身份或产品参考按需对照一次。
3. 选择承载核心因果、证明或连续性的关键视频段审查。
4. 合成后对完整视频做一次终审。
同一个未变化文件不重复送审。单段本身就是完整试片时，关键段审查与终审合并。
## 动作故事板审查
故事板作为视频动作参考时，只审它能否正确传递动作，不按成片美术质量评价：
- 面板数是否与单元时长和动作密度匹配，是否为凑九格重复姿态或虚构事件。
- 是否从初始姿态连续覆盖起势、主路径、接触/命中、反馈/反作用、落点与稳定状态。
- 红色主体路径、橙色旋转、蓝色摄影机、黄色接触点和红色虚线受力方向是否统一、无左右矛盾。
- 每格相对时间是否覆盖完整单元，首尾状态是否与计划和相邻段一致。
- 是否误增未登记人物、道具、场景、文字或玩法状态。
- 长距离场景路线是否与 route map 一致；故事板只能截取当前单元的局部路线。
- 图与同名 JSON 是否一致，且后续视频请求是否真实绑定该故事板。
线稿简陋、弱色彩和简笔人物不是缺陷；漂亮写实但缺动作链、接触点或轨迹才是不通过。箭头、格号、时间标签和说明字若进入最终视频，按参考污染处理。
## 单变量复刻先查修改范围
- 先核对模式、母片、实际请求和“允许改变／必须保持／因果适配闭包”。任何画面变化必须属于允许集合，或能逐项还原“新条件 → 原假设失效 → 最小适配 → 保护项”；否则按非目标污染处理。`edit_in_place` 可评价逐帧保持；`structural_remake` 只评价结构合同，不得宣称其他像素不变。
- 换场景逐镜对照人物身份/数量/目标/关键事件/字幕/HUD，并把纯视觉换景与已批准的服装、步态、接触、受光或环境声适配分开验收；换人物逐镜对照场景、其他人物、动物、道具、动作、切点、文字/HUD；换玩法逐镜锁人物与背景身份，核对输入到动作、接触、反馈、资源/UI/声音的完整新闭环。三类都核对总时长、画幅、节奏证据和原音轨处理。
- 结构重建缺失起势、路径、接触或结果，二合一变三合一，切鱼变砸物，人物/场景/剧情越权改变，字幕改写或原声丢失均为硬伤；身份或轨迹细节无法逐帧一致时记录为模式能力边界，不伪装通过。
- 同一结论冲突时保留争议并定位证据；不得重问直到通过，不得把供暖写成助暖、删字幕或改CTA解释为等价保留。

## 完整母片单变量终审

终审必须落盘 `review_final.json`，顶层
`contract: vibefilming.review-final/v1`，并逐项给证据：

- 完整视频可全片解码，首帧、末帧和每个内部切点可读取；全片联系表与全部接缝证据存在。
- `full_timeline.json` 从 0 到末帧无缺口、重叠或代表段替代；每段
  `affected` 与实际复用/生成来源一致。
- 真人实拍、可识别人脸或疑似真人范围均直接复用源片，未出现在模型动态/图片参考中。
- 所有 `affected=false` 区间画面职责不变；`affected=true` 只兑现唯一变量，无人物、
  背景、镜头、字幕/HUD/数字/CTA、图标或声音污染。
- 成片顺序、原切点、反馈间隔、最大空窗、画幅与分辨率保持；任一微调速不超过 2%。
- 源片与成片精确时长误差不超过一帧；完整原音轨覆盖全片。视觉模型不能听音时，
  使用媒体流、时间轴和音轨回铺记录验真，并把主观听感标为未验证。
- `generation_units.json` 中每个单元均有 ≤15 秒精确动态参考、私有 sidecar、
  故事板真实绑定、Seedance task ID、最多两次提交和明确选择结果。

存在缺镜头、真人段生成、时长超一帧、原音轨丢失、锁定层被改或交付文件不可访问时，
结论只能 `partial|blocked`，不得因 MP4 可播放写 `passed`。

## 游戏检查

游戏审查必须同时看“画面里有什么、它长什么样、它怎么动、为什么变化”，不能只检查是否穿模。

### 审片记录格式

每个问题都写：

`时间范围 + 画面区域 + 对象 + 可观察动作/状态 + 与目标的差异 + 交付影响`

先描述证据再下结论。例如不能只写“动作没逻辑”，应写“3.2–4.1 秒，画面右侧弩塔未发射，敌人却在无命中反馈时消失，掉落金币因此没有来源”。

审查结论只对照用户要求、已确认玩法合同、原片可观察事实和实际生成要求。不能因为“通常售卖会加钱”“黄色线看起来像牵引线”等类型经验，就发明奖励、机制、数值或特效职责。目标规则没有证据时写“无法判定”，不能据此打回；最小修复也不得擅自给出 `+15/+25` 等新数值。

审查范围开始时已经存在的对象和状态，默认视为合法初始条件；不能要求成片补拍范围之前的来源。只有计划明确要求展示前置动作、初始状态与参考冲突，或对象在审查范围内发生无触发变化时，才按因果缺失打回。

### 1. 场面完整性

逐段核对：

- 地图边界、道路/格位/平台、入口出口和固定地标是否稳定。
- 角色、敌人、NPC、建筑、资源、交互区和障碍物是否齐全。
- 对象位置、朝向、数量、遮挡、画内/画外和再入画关系是否连续。
- 前中后景、主体占比、操作区和安全区是否仍支持玩法理解。
- 只换环境时是否误改角色、敌我、塔、资源和 UI；全换皮是否漏掉后续新对象。

对象暂时出画不等于消失；再入画时身份、状态和数量必须接得上。

### 1.1 全场景背景覆盖

用户要求一个场景从头到尾换环境时，按真实切镜逐镜审查，不能只看成功的代表帧：

- 列出范围内全部 `shot_id / 时间范围 / 机位 / 应见目标环境 / 实际环境`。
- 每个镜头分别检查天空、远景地标、中景结构、地面或水体、天气与环境光。任一可见层仍属于旧环境，该镜头即未覆盖。
- 计算 `已完整替换镜头数 / 范围内总镜头数`。只有覆盖率 `100%` 才能通过“全场景换背景”；首镜、某个特写或若干秒成功只能判失败并定位漏镜头。
- 跨切镜核对目标环境身份：地标方向、地平线、昼夜、天气、调色、主光和材质语言必须连续。每镜都换了但彼此像不同地点，也不通过。
- 人物身份、目标、关键事件、数量、字幕、HUD、切点、镜头时长和节奏落点仍按保留合同检查；纯视觉换景额外锁动作，环境条件变化只放行账本内的最小适配，不能为了背景覆盖牺牲主体。
- 最小修复只重做漏换或环境身份漂移的镜头，再按原切点回装；不得建议整段原样重抽或用叠化、模糊、裁切遮住旧背景。

### 2. 画风与视觉一致性

核对可观察画风，不只写“风格一致”：

- 2D/2.5D/3D、写实程度和人物比例。
- 角色、建筑、道具的轮廓与造型语言。
- 地面、水体、木材、金属、布料和粒子的材质。
- 主色、辅色、点缀色、饱和度、对比度、阴影和光照。
- 全局昼夜、天气与局部灯光是否按事件变化，固有材质颜色是否被误改。
- 特效和 UI 是否属于同一美术体系，有无模型乱码或其他品牌残留。

美术偏好属于业务反馈，但明显换画风、换产品、身份漂移或参考污染属于硬伤。未授权改画风时，写实变 3D/动画、3D 变真人实拍及 2D/像素/黏土等跨媒介变化直接不通过；同时检查人物比例、材质和光照是否漂移，故事板线稿不得成为成片改媒介的依据。

### 3. 人物与对象运动

每个关键动作检查：

- 起始位置/姿态是否成立。
- 起势是否由输入或自动触发引起。
- 路径、方向、速度、重心、左右肢体和接触点是否连续。
- 武器、工具、弹道、资源和交互区是否真正发生接触。
- 命中/收集/建造/升级后的落点和稳定状态是否成立。
- 头发、衣摆、武器、掉落物等次级运动是否跟随正确物理来源。

需要完整动作链时，缺起势、缺接触或直接跳到结果都不通过。原片已经提供速度合同时，可观察的跨屏位移、动作耗时、事件频率和无反馈空窗属于可测事实；超出合同允许偏差时按复刻偏差处理。合同以内是否“爽”、操作响应和手感偏好仍记录为待业务判断，不能由机器代签。

### 4. 速度与节奏

复刻审查必须对原片和生成片使用同一测量口径：

- 首个有效玩法动作时刻。
- 同类主体每次移动的起止时刻、跨屏比例、耗时及 `%屏宽/秒` 或 `%屏高/秒`。
- 瞄准、起势、发射、命中、拾取、交付、建造和升级耗时。
- 攻击/命中/掉落/合并频率、每5秒有效动作与反馈数、平均及峰值反馈间隔。
- 操作、观战、转场和收尾停顿，以及最大无反馈空窗。
- 镜头跟随/平移的方向、跨屏比例和耗时；固定镜头是否发生非预期漂移。

默认允许 `±20%` 的测量误差；用户或玩法合同给出更严格阈值时服从明确阈值。生成片慢于原片超过该范围、首个动作明显延后或无反馈空窗超标，属于客观节奏偏差。即使总时长更短或事件更多，也不能据此判定节奏达标。

提速造成动作链缺接触、结果提前、对象复制、状态跳变或镜头失稳时，优先判因果/连续性硬伤，不能用“节奏更快”豁免。审查应分别报告“速度是否复刻”和“因果是否完整”。

审查前核对已确认模式与真实输入。`edit_in_place` 或明确要求原运动保真时，必须实际传入对应母片视频；仅有静态帧时写“不通过：输入不具备所要求的运动保真条件”。用户已选择 `structural_remake` 时，按结构合同核对状态、动作因果、数量、切点和节奏测量，不因没有动态参考自动判失败；逐帧运动无法验证应记为能力边界，不得宣称原运动完全保留。

### 5. 镜头运动与空间

- 固定、跟随、平移、推进、拉远、旋转是否符合计划或原片。
- 镜头运动和角色/地图运动是否被正确区分。
- 相机位置、俯仰角、主体尺度和地图拓扑是否突然变化。
- 敌我方向、移动方向和地标关系是否翻转。
- 固定 HUD 是否随镜头漂移，世界标签是否脱离对象。

未经设计的旋转、环绕、浅景深、推近或切镜，只要影响操作区和空间理解即为硬伤。

### 6. 特效与反馈

逐个事件核对：

- 瞄准或预警是否先于攻击。
- 发射物是否从正确主体产生并沿可辨路径移动。
- 命中特效是否出现在真实接触点，受击对象是否给出对应反应。
- 掉落物是否来自被击败/完成的对象，收集路径是否进入正确角色或资源槽。
- 建造/升级是否先有投入和触发，完成后外观、等级和能力是否持续。
- 特效形状、颜色、方向、范围和持续时间是否符合画风与事件。

粒子、闪光和震动不能替代真实反馈；没有命中却爆炸、没有掉落却涨资源、没有投入却升级均为硬伤。

### 7. UI、文字与状态

- 固定 HUD 的锚点、按钮、进度、数字和安全区。
- 世界标签、飘字、血条和教学手势是否绑定正确对象。
- UI 内容变化是否对应玩法事件；精确文字是否走既定生成/合成轨。
- 资源、数量、等级、建筑、伤害和奖励是否有依据地变化。
- 中段状态是否被提前到开场；建成/升级后的结果是否回退。

原生字幕检查逐字内容、时机、位置、可读时长与遮挡。乱码、错误品牌或重复字按交付影响处理；修复相关生成段后也要检查动作和相邻衔接，不能假设底片仍未变化。

只有玩法合同明确要求某次事件更新 UI，未更新才是硬伤。仅观察到“交付后数字仍为 0”，但没有确认交付是否付费、奖励是多少时，只记录现象和信息缺口。

### 7. 因果复述

审完后必须仅凭成片复述：

`初始目标 → 玩家输入/自动触发 → 动作传播 → 命中/交互 → 反馈 → 资源/状态结果 → 下一目标`

如果只能描述“一堆东西在动”，无法指出输入、反馈和状态结果，玩法因果不通过。

### 7.1 剧情改写一致性

剧情改写不只检查新对象是否出现，还要检查新设定是否真正支配人物行为：

- 复述新关系、新意图和新目标，再逐项检查身体动作、表情、接触、反馈、字幕、对白和音效是否表达同一事实。
- 角色从敌对改为友善时，旧踢击、攻击、格挡、逃跑、受击、伤害和敌意表情若仍无新理由地出现，属于剧情硬伤。
- 友善互动必须看见接近或示意、真实接触、双方响应和稳定结果。例如“贴贴”要看到靠近、接触和回应；“登鲸”要看到鲸鱼低头、人物迈步接触并站稳。
- 硬切直接从准备状态跳到已接触、已登乘、已获救或已和解，缺少计划要求的关键过程时不通过。
- 原字幕、对白或音效仍描述旧敌对剧情时，即使画面主体已变友善也不通过；固定免责声明和无关 HUD 不受影响。
- 节奏快不能豁免因果缺口。前 `1–2 秒`有核心事件，同时完整保留接触和反馈，才算高节奏剧情成立。

### 7.2 生成式重制对齐

生成式重制不按“是否逐帧像原片”判定，而是同时核对正式新剧本和已选复刻元素：

- 新主线从开场到结局能独立复述，不需要观众知道来源视频才能理解。
- 每个角色的目标、行动、接触和结果都来自新剧本；来源剧情中的人物关系、旧动作、旧字幕或旧反馈没有无意残留。
- 明确保留的钩子机制、切镜密度、情绪曲线、反馈频率、反转位置和 CTA 功能在新表达中仍成立。
- “保留功能并重写表现”的元素只比较叙事作用和节奏位置，不要求复制来源对象或具体动作。
- 每个来源元素都能解释为原样保留、功能重写或放弃；无法解释的旧内容视为参考污染。
- 场景、人物关系或玩法规则改变后，相关物理条件已随之重建，没有在新世界里继续执行不成立的旧动作。
- 正式字幕、对白、声音和画面动作表达同一个新剧情；仅有画面变化而声音仍讲旧故事时不通过。

终审分别报告“新剧本完整性”和“复刻元素达成度”。不能因为不再复现原剧情而扣分，也不能因为镜头很像原片就忽略新剧情不成立。

轻微边缘瑕疵、装饰粒子和符合玩法规则的自动吸附不阻塞。玩法手感、美术偏好、节奏细腻度和声音必须来自真实业务反馈，机器视觉通过不能代替业务签收。

## 电商检查

- 产品、包装、Logo 和核心人物是否稳定。
- 产品名、卖点、价格权益和 CTA 是否正确。
- 使用动作是否可信，证明是否看得懂且未误导。
- 前三秒和整体节奏是否支持转化。
- 生图是否真实输入产品图；含商品主体的生视频调用没有同时绑定真实产品图和场景视觉锚点时不通过。

## 影视检查

- 主线和关键因果能否理解。
- 核心人物、道具和空间是否连续。
- 关键动作是否可信。
- 风格是否严重漂移。
- 是否缺段、损坏或画幅错误。

## 客户反馈专项验收

- 必说句逐条记录 `line_id / 目标原文 / 实际听到内容 / 时间 / 是否完整 /
  音频证据来源`，报告完整句数与必说句数。音轨存在、字幕正确、嘴动都不能证明
  口播覆盖。当前视觉工具不支持听音时标“口播未验证”，由真实听音/可用音频工具
  补证据；不得让VLM从嘴动猜出语音。无口播任务为N/A。
- 可见说话者检查嘴部动作时段与台词排时，画外旁白不做口型失败。
  漏句、错产品名、末字截断、声线明显不符已确认角色均定位到本句，不重做无关镜头。
- 对照情绪账本，记录触发时刻、脸部可见性、眉眼/目光/嘴角、重心/手势
  是否从起点发生目标变化。全片同一表情、无触发表演和关键反应不可见分别报告。
  只对有可观察约定的差异判失败，主观感染力仍留给业务验收。
- 节奏记录首事件时刻、主要反馈间隔与最长无效等待；用实际时刻对照计划，
  不以视频变短替代速度验收。提速导致接触消失、结果提前或语句不可听清仍失败。
- 分开报告技术可播放、路径与工具执行、口播、表演、节奏和整体任务达成；
  未验证维度不能被“视觉通过”覆盖。20%–30%是客户当前反馈，不能当新版本实测可用率。

## 判断经验

先区分三种结论：

- **硬伤**：事实、身份、因果、文字或交付错误，必须修复。
- **主观反馈**：合同范围内是否够爽、手感、审美、节奏偏好和声音偏好，需要真实业务判断；可测速度偏差不归入此类。
- **投放结果**：CTR、CVR、CPI、ROAS 等，只能来自实际投放。

机器审查只对第一类负责，不能拿画面无穿模代替业务认可，也不能拿业务喜欢代替事实正确。

审查时先描述可观察证据，再下结论。不要把“这是预期效果”“上一版已经修好”等答案写进审查问题。成片可能因为强参考碰巧做对，但错误的计划或生成要求仍应作为流程问题记录，避免批量复制。

## 常见 bad case

- 每个素材都审一遍，成本很高，却没有选中真正承载风险的关键段。
- 单段看起来正确，就忽略完整成片中的缺段、重复奖励和状态回退。
- 修复原生字幕后没有核对动作，遗漏新出现的玩法或衔接错误。
- 把轻微边缘变形和核心角色换脸放在同一严重度。
- 无业务反馈却写“手感通过”“声音通过”。
- 没有投放数据却写“爆款”“转化提升”。
- 全场景换背景只抽查成功镜头，遗漏后续镜头恢复旧环境。
- 新角色被描述为友善，但仍沿用原片无理由的踢击、逃跑或伤害反馈。
- 新剧情靠硬切跳过关键接触，却只因首尾结果正确而判通过。
- 生成式重制仍按逐帧相似度审片，逼迫新片恢复已经明确放弃的旧剧情。
- 新片复制了原镜头和动作，却没有兑现选定钩子、反馈密度或反转功能。

## 修复

- 参考错先修参考，计划错回计划，生成要求漏项回编译，剪辑错回合成。
- 局部错只修受影响对象或片段，不原样重抽整段。
- 原生文字错误只定向修相关段，复核文字及可能变化的动作、身份与衔接。未变化的段不重复送审。
- 审查只输出根因、最小修复范围和当前版本是否通过，不调用执行器状态命令，也不决定
  还能提交几次。是否实施修复由总控消费 `vibefilming.generation-unit-status/v1`
  后决定；执行阻塞时仍有硬伤，结论必须为“不通过”或“最佳可用但未通过”。
- 修复计划必须点名时间、区域、对象和正确状态；保留已正确的场面、画风和动作，只修改根因覆盖的最小范围。

## 多段接缝
- 同时读取版本化 timeline 与执行器产出的接缝证据；每个相邻终版片段对照切点前后
  证据帧，并记录 `at / cut_class / continuity_strategy / transition / 证据引用 /
  PASS-FAIL`，禁止只凭整片观感写“丝滑”。具体抽帧工具和参数属于执行型 Skill。
- 先按当前 capability 验收选型：同机位连续内容未超过单次上限却无理由拆段、超限
  长镜头在支持延长时没用上一段完整视频、带故事板/身份/环境/音频却选择了互斥模式，
  或母片硬切被强行串行，均作为流程阻塞；画幅和参考互斥只认当前 schema。
- 再审画面：`same_scene_continuous` 检查位置/尺度/姿态/动作相位/运动/道具/UI/主光/机位；`same_scene_elliptical` 检查跳时可读；`scene_change` 检查特效触发、峰值、清除及颜色/方向/速度。突跳、重复、冻结、状态回退、无动机滤镜或携带故事板符号均不通过。
- 证据审查同时检查黑帧、破帧、双影/双字和可见字幕，不能判断音频截断。修复按根因
  分流：长镜头回到延长策略；无其他参考的串行新段才用严格首帧；必须保留故事板、
  身份、环境时用边界图软锚点；原片硬切只调各自裁点。最后才在双方静止且无关键
  文字时考虑短叠化。
## 输出

- 存在必改背景/对象残留、未授权换演员/媒介、改切点、末段冻结或替换范围缺失时，整片结论为“不通过”，即便文件可播放也只能称最佳可用/部分交付。不得以“有条件通过”把明确合同缺陷包装成整片成功；分别报告技术可播放性与任务达成度。
- 核验所选视频和审查文件确实保存于当前项目，并核对交付清单的范围、状态、残留项
  与真实文件一致。平台 idle、工具 success 或出现 MP4 均不等于任务完成。
- 完整母片单变量任务还要核验 `delivery_manifest.json`、`full_timeline.json`、
  `generation_units.json`、`review_final.json`、全片联系表和接缝证据均进入
  当前项目且可通过 Studio 下载或本地文件访问；缺任一项不得写最终成功。
- 通过：列出足以放行的可观察证据，并标明尚未做的业务或投放验证。
- 不通过：只列阻塞项和最小修复。
- 某维度证据不足时写“未验证/无法判定”，不得写“部分通过”来掩盖缺少画风、材质、运动或声音证据。
- 没有音频审查、业务反馈或投放数据时，明确写“未验证”，不得推断通过。
- 本文件已经包含审查、修复和复核边界；孤立审查问题不再读取流程总控或通用验证 SOP。
- 审查记录必须写明本次实际用了原视频还是仅用了状态帧；后者只能评“状态重建”，不能给“原运动复刻通过”。参考下载/策略拒绝属于输入失败，不是画面质量结论。
- 状态帧重建出现对象复制、数量无来源变化、瞬时帧提前或机位漂移时，根因标为“缺动态参考”，不得建议仅靠改 prompt 重试。
