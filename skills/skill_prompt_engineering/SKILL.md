# Skill · 生成要求编译
## 职责
每次只为一个明确生成对象编译一份要求。上游计划决定拍什么，本 Skill 只负责让模型看得懂并确保实际输入一致。
正文使用中文。原片负责哪些节奏与动作、目标素材替换哪些外观，要在开头说清；不为“高级感”额外加入慢动作、环绕镜头或等待。
## 编译步骤
1. 明确对象、时长、画幅、声音和本次目标。
2. 读取已定稿计划与逐字文本；两者冲突时停止，不自行改写。
3. 列出实际会传入的每张图或视频，以及它负责锁定的内容。
4. 写清镜头、主体、材质、空间、环境、光线、色彩和时间变化。
5. 核对真实调用设置与正文一致。
6. 输出可机读自检：顶层 `status`、`prompt_ready_for_generation`、`items`、`blocking_findings`、`decision`；`items` 至少含 `plan_fidelity`、`seven_layer_detail`、`time_axis_motion`、`reference_binding`、`storyboard_boundary`、`continuity_and_props`、`expression_and_secondary_motion`、`generation_settings_match`、`prompt_specificity`，值以 `PASS:`、`BLOCKED:` 或 `N/A:` 开头。`PASS` 不得有阻塞子项且 findings 为空；`BLOCKED` 时 ready=no，findings 列 `category`、`rule_id`、证据和 `required_fix`，修复并重检前不得调用模型。
## 参考素材
- 没有实际传入的参考，不得声称“已参考”。
- 每项参考只承担明确职责，例如身份、外观、空间、状态、动作或色彩；同时写清不继承什么。
- 动作故事板必须作为本逻辑视频单元的真实参考图传入，并读取同名 JSON；按相对时间逐格翻译主体路径、旋转、接触/命中、受力/反馈、落点和摄影机运动，不得只写“参考故事板”。
- 不把故事板的线稿画风、面板边框、箭头、编号、时间标签和说明字生成进成片；角色身份仍看角色卡，场景结构仍看场景参考，整场长距离路线仍看 route map。
- 不把全项目素材全部塞入一次调用。
- 含商品主体的项目禁止裸生成视觉素材；生图需要真实产品图，生视频还需要本段的场景或关键帧锚点。
- 真正连续延展上一段且当前 capability 支持 `extend` 时，实际传入上一段终版视频，
  正文写“向后延长视频1，从末态继续”；普通切镜不套这条规则。严格
  `first_frame/last_frame` 与普通多模态参考的互斥关系只认当前 schema。
## 接缝与转场编译
每个单元读取相邻接缝合同；缺 `cut_class`、首尾状态或策略时不得自行补“丝滑转场”。详细编译按本目录手册的首尾状态与段间承接章节执行。
- `same_scene_continuous`：同一长镜头用上一段完整视频 `extend`；同场景新段若串行且无需其他参考，用 `extract_boundary_frame` 的真实末帧作严格 `first_frame`，终态稳定时可再加同画幅 `last_frame`；若角色/环境/故事板参考不可缺，末帧改作 `reference_image` 软锚点并在正文指定为开场关键帧。三种路径不得混传，均按“末态→第一动作→后续动作”写清。
- `scene_change`：同一有因果来源的遮挡、风雪、浪花、烟尘、闪光等在上段进入达峰值，下段以同颜色/方向/速度开场并在 `0.20–0.50 秒`内清除；不改变人物/剧情/玩法/文字，无共享桥时才交给短后期转场。
## 先判生成模式

创作权限只来自用户授权，复刻默认 `replacement-only`，不因模型重新生成像素而扩大范围：

- `edit_in_place`：只改用户点名的主变量和已登记的因果适配闭包。纯视觉换景不改人物动作；真实环境条件使原衣着、步态或接触失效时，只编译有完整因果链的最小联动。其余镜头、切点、时长、画幅、字幕、HUD与声音保持。
- `structural_remake`：用户明确不用视频编辑时，不传原片视频；实际传入本镜源状态帧、身份参考和目标变量参考，按拆镜重建同一剧情、镜头职责、动作拓扑、数量、接触、反馈、字幕和时长。提示词不得写“逐帧不变”或声称运动来自原片。
- `generative_remake`：仅当用户明确授权重写剧情或自由创作，才编译获准部分的新剧本；未授权部分仍锁定。换参考图、模型重生成、多个外观变化均不授权改故事。
- 生成式重制中，原视频只锁上游明确选中的节奏、构图、画风或镜头功能；新剧本独占人物动机、事件顺序、动作、接触、字幕和声音。

## 单变量替换优先

只有模式已确定为 `edit_in_place` 时，才使用以下规则：

- 先列 `允许改变 / 必须保持 / 因果适配闭包`；闭包每项必须写“新条件 → 失效的原假设 → 最小适配 → 仍锁定内容”。有可用原视频时，原视频控制闭包以外的镜头、动作、节奏、接触、场景、其他对象、文字版式和 UI，目标素材只控制指定变量。
- prompt 第一行直接写“只把视频1中的 A 替换为图1中的 B”，随后只写保持项、物理适配和禁止连带变化。
- 不重述原片完整剧情和逐秒镜头，不增加“电影感、氛围升级、重新设计”等创作词。重复发明时间轴会把编辑任务退化成重拍。
- 一版只换一个指定变量；不同版本独立从同一母片生成。提交前逐句检查 prompt 是否越出“允许替换项”，出现新剧情、新字幕、全局改画风或未授权第二变量立即 `BLOCKED_SCOPE`。
- 商品替换必须检查包装结构与原动作是否同构，人物替换必须保持骨架和接触点，游戏角色换皮必须保持玩法状态机与 HUD。
- 本单元若包含明显运动、接触、击退、翻滚、收集、合并、建造或升级，缺少已落盘的动作故事板图与同名 JSON 时立即 `BLOCKED_STORYBOARD_MISSING`；静态展示镜头可在计划中写明免故事板理由。
- 原视频不可访问时阻塞 `edit_in_place`；只有用户明确选择 `structural_remake` 才可改用源状态帧逐镜重建，并把验收口径降为结构保持而非逐帧保持。
- 完整母片单变量编辑只编译 `generation_units.json` 中的 `affected=true` 单元。实际
  视频输入必须是沙箱内精确裁出的源段经私有 sidecar 发布后的动态参考，总长不超过
  15 秒；使用 Seedance 2.5 `edit`、`ratio=adaptive`、`duration=-1`、
  `generate_audio=false`。prompt 不得含对白、喊叫、口型、唇同步、音效或声音生成
  语义；最终完整原音轨在合成阶段回铺。
- 字幕/HUD/数字/CTA、图标、出现时机和完整原音轨未被用户点名时绝对锁定，不能放入
  允许改变或因果适配闭包。生成正文只描述视觉玩法替换，并明确这些层逐字逐时保持。

商品换品、人物换角、环境替换、玩法替换和游戏角色换皮的精简模板与物理合同见 `references/replacement_edit.md`。命中时只读取对应章节。

## 全场景背景替换

用户要求把一个连续场景“从头到尾”换成新环境时，目标是全镜头覆盖，不是让模型自行挑几秒修改。

- 先读取真实切镜表，列出替换范围内每个镜头的 `shot_id / source_range / 景别 / 机位 / 可见环境层`。首镜替换成功不能代表整个场景成功。
- 多切镜视频默认按真实切点拆成单镜头生成单元。一个生成单元只负责一个镜头中的环境替换；不得把含多个机位的长视频一次提交后期待模型跨镜头持续换景。
- 单镜头短于模型最小时长时，以该镜头作为参考视频开头，向后补足调用时长作为生成把手；合成只取该镜头的精确原始时间范围。补入的后续镜头不是本单元交付范围。
- 所有镜头使用同一个目标环境身份包。至少包含一张主环境锚点；反打、俯视、近景或室内外关系无法由主图确定时，先补同一环境的对应机位图，不靠每段文字临场重建设定。
- 每条 prompt 第一行写清“替换本生成单元内所有可见环境层”，并列出该镜头实际可见的天空、地面、水体、远景地标、中景结构和环境光。只写“换远景与天空”不能覆盖镜头里同时可见的地面或中景。
- 角色身份、目标、关键事件、数量、字幕和 HUD 继续由原视频锁定；纯视觉换景保留原动作，真实环境条件变化只执行覆盖账本中已登记的服装功能层、步态/发力、足迹、风力反应、受光或环境声适配，不把目标图的空前景理解为删除动态对象。
- 维护逐镜覆盖账本。每个镜头必须有输入视频、环境参考、实际输出和审查结论；任何镜头仍露出旧环境时只重做该镜头，不把“部分镜头成功”写成全场景完成。
- 合成按原切点和原顺序回装。背景替换不得新增叠化、删镜头或改变镜头时长来掩盖未覆盖区域。

全场景背景 prompt 只写当前单镜头能看到的环境层，不在每条请求里复制整段剧情。跨镜头一致性由同一环境身份包和逐镜覆盖账本保证。

## 剧情改写与动作失效

改变角色关系、事件性质、目标或结果时，不再属于 `replacement-only`。原视频只能继续约束角色身份、画风、空间基础、镜头节奏或切镜密度；原动作和接触不再默认保留。

- 先写新因果链：`新前提 → 新意图 → 起势 → 路径 → 接触 → 对方反应 → 状态结果 → 下一目标`。
- 建立旧动作处理表，把原片每个关键动作标为 `保留 / 替换 / 删除`。凡是依赖旧剧情前提的动作都自动失效，必须显式替换，不能静默继承。
- 角色从敌对改为友善时，攻击、踢打、躲闪、受击、逃跑和伤害反馈默认全部失效；改成与友善意图一致的试探靠近、放下戒备、贴贴、递送、抚摸、合作或庆祝动作。
- 新接触必须拍出起势、接近、真实接触和双方反馈。不能用硬切直接跳到“已经贴贴”“已经坐上鲸背”“已经获救”的结果。
- 字幕、对白、表情、音效和 HUD 中与旧剧情冲突的内容一并改写；与剧情无关的免责声明、品牌和固定 UI 才保留。
- 新链条仍服从高节奏要求：前 `1–2 秒`出现核心事件，压缩等待而不省略接触和反馈。
- prompt 开头直接声明“剧情改写，以下新因果链覆盖原视频中冲突的动作”；不得同时写“全部动作原样保留”。

调用前逐项检查：新角色意图、身体动作、接触结果、字幕和声音必须表达同一个剧情事实。任一层仍服务于旧剧情时返回 `BLOCKED`。

## 游戏生成重点

- 只换环境时不得顺手重画角色、塔和 UI；环境规则确实改变移动或接触时只改已登记的最小适配。只换玩法时锁住人物与背景身份，只改用户点名的玩法对象及必要输入、动作、接触和视觉反馈；UI、字幕、数字、CTA 与声音未获明确授权时保持。全换皮时只替换已授权且有参考的对象。
- 原位编辑中原视频用于动作与事件、目标图用于外观；结构重建由源状态帧、保留稿和数字化动作链控制，只评价状态与动作拓扑；生成式重制中新剧本用于动作与事件。要求保留原运动却没有视频输入时必须阻塞。
- 原片驱动转绘时，把当前原片片段留作唯一视频输入；上一段结果只用已验证的末状态帧承接。提交前确认视频 URL 本次仍可访问且未过期，本地路径或历史签名 URL不算已传入。
- 没有视频输入时，一个生成单元最多承担一个原子动作；涉及对象数量变化、形态转换再交付、升级后自动化等多次状态转移必须阻塞。参考帧若处于对象悬空/转化中，或彼此机位、数量、角色集合不一致，也不得合并驱动动作。
- `edit_in_place` 把当前完整生成单元的原片范围放入 schema 指定的视频参考字段，长度
  符合当前 capability；2–5 秒只是动作测速/代表观察范围，不是强制生成分段长度。
  同机位连续内容未超过单次上限时优先保持整段，不能按采样窗拆成许多短块。
  `structural_remake` 则把动作前/后源帧、身份图和目标变量图放入 schema 指定的图片
  参考字段，正文完整编译“状态前→起势→路径→接触→反馈→状态后”，不得偷换为自由生成。
- 保持原镜头方式、地图关系、操作顺序、资源变化和持续状态。
- 空环境图不删除动态对象，中段设计帧不改写开场。
- 全局昼夜和局部亮灯是不同事件；未知画外变化不得补造。
- 字幕、HUD 数字和 CTA 默认由模型原生生成；逐字内容与对应事件绑定，不能提前发奖励或擅改余额。

## 游戏正文编译层

最终视频要求按以下顺序写，任何一层不能只剩“保持一致”：

### 1. 镜头

- 视角类型、俯仰角、景别、主体占比和地图可见范围。
- 固定/跟随/平移/推进/拉远/旋转，以及开始、结束和速度。
- 镜头运动与角色运动分别描述；固定 HUD 不受镜头运动影响。
- 原片已有镜头语言时逐项保留，不能同时写互斥指令。

### 2. 场面

- 地图边界、道路/格位/平台、入口出口、固定地标和前中后景。
- 当前可见角色、敌人、NPC、建筑、资源、交互区、障碍物及相对位置。
- 暂时画外但会再入画的对象明确保留，不因参考图没拍到而删除。
- UI、世界标签、教学手势、特效和游戏世界的图层关系。

### 3. 画风与材质

- 媒介与写实程度、人物比例、轮廓和造型语言；复刻逐字继承来源媒介并排除互斥媒介：写实排除 3D/游戏 CG/卡通/动画脸，3D 排除真人实拍与 2D 插画，其他媒介同理。用户未授权改画风时出现跨媒介词或冲突参考，立即 `BLOCKED_STYLE_DRIFT`。
- 角色、建筑、地面、水体、金属、木材、粒子和 UI 的材质特征。
- 主色、辅色、点缀色、饱和度、对比度、阴影、昼夜与局部灯光。
- 允许替换与必须保留的视觉对象逐项列出。

### 4. 主体动作

每个动作都写：

`起点 → 起势 → 路径 → 接触/命中 → 反馈 → 落点`

具体到位置、朝向、速度、重心、左右肢体、武器/工具、弹道、交互对象和停止状态。多主体使用稳定称呼，不用“他/它”造成误绑定。

### 5. 次级运动与特效

- 衣摆、头发、武器、拖尾、掉落物、资源吸附、环境粒子如何由动作带动。
- 瞄准、发射、命中、受击、收集、建造、升级特效各自的触发、位置、颜色、形状、方向和持续时间。
- 屏幕震动、闪白、冲击波和数字跳字只在对应事件后出现。
- 不用“炫酷特效”概括，也不用粒子掩盖缺失动作。

### 6. UI 与声音

- 固定 HUD 的位置和允许变化的内容；原生文字的逐字内容、出现时间及可读时长。
- 世界标签是否跟随对象，教学手势是否属于成片。
- 每个点击、发射、命中、收集、建造和升级的音效节点。
- 未计划的声音不自行补造；对白与字幕是两项要求，分别写明声音和显示方式。

### 7. 时间轴与状态

每阶段同时写场面、主体运动、次级运动、镜头、特效、UI、资源和声音的变化。动作结果必须成为下一阶段起点；已建成、已升级、已消耗或已掉落的状态不能回退。

游戏 prompt 的目标不是“细节尽量多”，而是每个变化都有唯一触发、唯一对象和可追踪结果。

### 8. 速度参数

原片复刻必须把速度合同直接编译进正文，至少包含与本次动作有关的四类数字：

- **位移**：如“角色在 `1.0 秒`内横向跨越约 `30% 屏宽`”，而不是“角色快走过去”。
- **动作**：如“起势 `0.2 秒`，弹丸在 `0.5 秒`内跨越 `30% 屏高`并命中”，而不是“迅速攻击”。
- **频率**：如“单点命中间隔 `0.4–0.5 秒`，爆发期反馈间隔 `0.2–0.3 秒`”。
- **空窗**：如“战斗期连续无有效反馈不超过 `0.7 秒`，转场不超过 `0.6 秒`”。

数字必须来自当前原片中同主体、同动作状态的测量结果；没有证据就标缺失并阻塞运动保真承诺。模型不擅长严格数值时，保留“时间段 + 起止位置 + 必须发生的接触/反馈”三重约束，不删除数字。

提速只允许压缩原片中的无效停顿或按原片快节奏区间提高位移、攻击和反馈频率。不得通过省略接触、跳过状态变化、提前显示结果，或在短时间内堆入更多独立动作来制造“快”。

原位编辑只描述允许修改项和保持项；结构重建必须显式写动作链、相对位置、时刻和稳定结果；生成式重制以新剧本为准。三种模式不得混写。

## 视频时间轴

- 正式调用时长、格式、参考数量和模式互斥只认当前执行能力返回的 capability 合同，
  本 Skill 不复制模型版本数字。
- `structural_remake`、`generative_remake` 或无动态母片的新生成，短单元通常写
  2-4 个变化阶段，长单元或复杂动作写 3-6 个；同机位连续内容在 capability 允许且
  信息不过载时优先一次直出；`edit_in_place` 不重建完整时间轴，只写授权变量时间
  范围、保持项和必要因果适配。
- 每阶段按需要写主体动作、反馈、道具、环境、镜头和声音变化，不机械填满。
- 段初状态必须来自计划；段末状态必须能供下一段承接。

## 口播与表演编译

- 逐句消费口播账本，实际请求写说话人、{逐字台词}、起止时段、重音与声线，
  字幕另写【逐字文字】。不能只要求字幕而遗漏声音，或只说“人物讲解”。
- 新口播必须真实启用audio；保留原声任务允许生成静音底片并回铺原完整音轨，
  但不得声称静音底片有新口播。画外旁白无需可见嘴动，可见说话者注明说话时段和口型。
- 情绪绑定本段事件、表情局部、目光、手势与声线，不用“有感染力”代替；
  强参考中的中性脸不应锁死整段表情，身份稳定与表情变化同时成立。
- 必说句能在本段说完且末字不被截断；长句重排时只调排时，不擅改用户逐字文本。
- 将计划中的反馈时刻与最大空窗编入当前单元。首事件提前、移动与反馈加速，
  不能把“快节奏”落实为跳过接触、整段慢镜或结尾冻结。
- 自检增加 `speech_coverage / emotion_performance / pacing_contract`，
  无该要求时N/A；声音配置与口播要求冲突时BLOCKED。
- 每个参考先从真实工具返回或素材索引取路径并核对存在；待生成素材与逻辑名字
  不算reference_binding通过。产品图解码失败先报告输入故障，不发送缺核心参考的请求。

## 编译经验

生成要求不是把所有规则堆成一段长文，而是消除歧义：

- 先写本次唯一目标，再写参考职责，最后按时间写变化。
- 正向要求描述必须发生什么；负向要求只拦当前高风险错误，不罗列无关禁词。
- 同一对象只使用一个稳定称呼，避免角色名、身份名和外观名交替造成串物。
- 数字、方向、位置和先后关系优先于“震撼、电影感、丝滑”等抽象形容词。
- 参考图已有不想继承的 UI、文字或背景时，明确排除并落实可执行的干净底片或覆盖方案。
- 模型能力不足时降低承诺，不使用“100%复刻”“精确骨骼映射”等无法验证的保证。

生成失败后先分类：动作因果错、参考身份错、空间状态错、文字层错，还是调用设置错。
只有生成正文遗漏时才改 prompt；上游事实或素材错误不能靠增加形容词解决。编译修复
修复请求的输入必须包含 `vibefilming.generation-unit-status/v1`；只有其中
`can_submit=true` 才编译下一次请求。阻塞时只输出现有最佳版本与失败证据。本 Skill
不调用状态命令、不查询任务、不读取私有日志，也不自行维护提交次数。

明确隐私/内容策略拒绝不进入提示词优化：保存原错误，停止受阻请求，不换调用模式
或改措辞试探。查询/下载恢复由执行职责处理。动态天数、计数与长字幕在执行器额度
耗尽后仍不可靠时，保留缺陷作为未通过项，不未经授权改用补烧、删字或重构时间轴。

## 常见 bad case

- 文字里说参考原视频，实际请求只传了抽帧。
- 视频 URL 过期/下载失败后仍反复提交同一地址，或删掉核心原片改用静态图却继续宣称运动保真。
- 同时要求保留原角色和把所有可见资产重新设计。
- 把中段目标图当首帧，导致建造、升级或奖励提前发生。
- 为了承接上一段视频，挤掉了本段真正需要的原片动态参考。
- prompt 写“不要文字”，但参考图本身已有无法稳定消除的字。
- 同一条要求既写固定机位又写跟随角色移动。
- 要求整段换背景，却把含多个切镜的长参考一次提交；结果只有首镜或某一镜换景，仍按全场景完成交付。
- 把敌对生物改成友善角色，却继续保留原片踢打、逃跑或受击动作，造成设定与行为互相否定。
- 剧情改写只改结果和字幕，省略新接触过程，用硬切直接跳到已获救、已登乘或已和解。

## Seedance 特殊符号

- `（音乐描述）`：音乐 / BGM
- `<具体音效>`：音效 / 环境声
- `{逐字台词}`：台词 / 实声对白
- `【逐字画面文字】`：标题标识 / 画面文字 / 屏幕叠字

这些符号是项目提示词约定，不是 API 语法或精确控制保证。字幕允许逐句原生生成；`{}` 表示说出的台词，`【】` 表示需要显示的文字，两者可相同但必须分别指定。不要把“不说话”等控制指令放进台词括号。

## 原生字幕与参考角色示例
以下仅示范编译方式，不可当作用户素材事实：
> 图1只锁定目标杯子外观，视频1锁定倒入、接触与水花的动作节奏。保留原片机位和动作起止，只把场景改成暖色厨房。0–2秒杯子入画并落稳，落桌时出现短促接触声；2–4秒液体连续入杯。1–3秒画面下方显示白字黑描边【一杯清爽】，保持两秒后消失，不遮挡杯子。无旁白。

有原片动态参考时优先简洁的保留/替换说明；只有存在明确遗漏或冲突时才补详细时间段。字幕采用短句、单一主样式、明确留白区；不能靠禁止全部文字来逃避乱码风险。

## 调用前硬门禁

- 计划和逐字文本冲突；请求改动既不在允许集合，也没有“新条件 → 原假设失效 → 最小适配 → 保持项”的完整因果证据。
- 关键人物、产品、场景、状态或动作参考缺失。
- 游戏正文缺镜头、场面、画风、主体动作、次级运动/特效、UI/声音或状态连续中的任一关键层。
- 原片复刻缺同类动作的跨屏位移/耗时、事件频率或最大空窗，只用“快速、紧凑、丝滑”描述速度。
- 用“攻击、收集、升级、自动化”等结果词代替起势、路径、接触、反馈和落点。
- 声称使用原视频，但实际只传静态帧。
- 结构重建只传一张瞬时帧却声称复制了原运动，或未传动作前后状态就要求复杂数量变化。
- replacement-only prompt 又完整重写原片时间轴、场景和镜头，导致单变量编辑退化成重拍。
- generative-remake 没有正式新剧本、复刻元素映射或完整新因果，却直接把来源拆镜稿编译成生成请求。
- 商品替换前未检查泵头/旋盖/喷嘴等机构是否同构，仍要求执行源商品动作。
- 人物替换同时改了背景、运镜、道具或其他人物。
- 游戏角色换皮同时重画地图/HUD，或改变攻击次数、命中时机与资源变化。
- 全场景背景替换没有逐镜覆盖表，或任一范围内镜头仍显示旧环境。
- 剧情前提变化后仍要求保留依赖旧前提的攻击、躲避、受击或逃跑动作。
- 新剧情只有结果，没有可见的起势、路径、接触和反馈。
- 用上一轮静态帧生成结果作为视频参考，继续声称其动作来自原片。
- 同一对象同时要求保留和替换。
- 同场景连续接缝缺上段真实边界参考，或 prompt 只写“无缝衔接”而没有位置、尺度、动作相位、道具和镜头速度。
- 跨场景转场没有可观察的触发、峰值和清除过程，或用特效遮盖本应修复的同场景跳变。
- 操作结果倒置、资源重置或状态无依据回退。
- 真实时长、画幅、音频开关或参考输入与正文不一致。
- prompt 含工具名、项目路径、JSON 字段或审批状态。
- 核心动态参考被拒绝时不得静默移除；先区分 URL 失效、下载失败与内容策略拒绝。只有可选参考可删除，原片不可用则 `BLOCKED` 或明确降级为状态帧重建。
- `vibefilming.generation-unit-status/v1` 已把该逻辑段标为不可提交。

## 本 Skill 的详细手册

需要影视通用深度时，按问题读取本目录 `references/handbook.md` 的对应章节：

- 上游消费、文字、声音、故事板和参考职责：“一、先消费上游”。
- 七层画面、时间轴、镜头、空间、材质和情绪：“二、把方案编译成画面”。
- Seedance 符号：“三、Seedance 特殊符号”。
- 修复与调用前检查：“四、生成要求怎么写”“六、放行自检清单”。
- 商品、人物、游戏角色的单变量视频替换：`references/replacement_edit.md`。

手册只补充本次生成需要的细节，不触发读取其他 Skill，也不要求把所有检查项机械塞进每条 prompt。

## 回报

只报告生成对象、实际参考及职责、关键设置和 `PASS/BLOCKED` 结论。阻塞时指出缺什么事实或素材，不输出流程状态。
