# Replacement-only 视频替换编译

本文件只处理一种任务：已有视频的动作、镜头、节奏和叙事成立，用户只要替换商品、人物、游戏角色或环境。它不是重拍脚本，也不是风格重绘。

## 核心原则

视频参考负责原片的时间、空间和未授权事实；目标素材只负责指定主变量。每个裂变版本先列三个互斥集合：

1. **允许改变**：用户点名的角色、商品、环境、玩法或文案。
2. **必须保持**：未点名的身份、环境、玩法、事件、数量、镜头、切点、时长、字幕、HUD、原声和节奏证据。
3. **因果适配闭包**：指定变化让原事实不再成立时所需的最小联动。每项必须写清“新条件 → 失效的原假设 → 最小适配 → 仍锁定内容”；没有完整链路就回到保持集合。

换人物时只允许骨架、握持、遮挡和服装随动适配，不改背景或玩法。换玩法时允许重建新规则所需的动作与反馈链，不改人物和背景身份。换环境时先区分纯视觉换景与真实条件变化，后者才允许最小服装/动作联动。各变体独立从同一母片生成，不在一个裂变结果上继续叠加另一变量。

先写一句唯一编辑指令：

`只把视频1中的［源对象］替换为图1中的［目标对象］。`

然后只写三组约束：

1. **保持不变**：镜头、时长、切点、主体轨迹、动作起止、接触点、反馈时机、场景、光线、其他人物/物体、UI 和非产品文字。
2. **替换后适配**：目标对象的尺寸、朝向、透视、受光、阴影、遮挡和接触关系如何匹配原位置；环境或玩法变化还要逐项引用已登记的因果适配。
3. **禁止连带变化**：不得新增、删除、复制、换景、换机位、改动作、改节奏或重写未授权文字。

有正确动态参考时，不再另写一套逐秒镜头脚本。重复描述原片会让模型在“视频证据”和“文字重拍方案”之间二选一，降低保真度。

## 环境替换

环境替换分两种范围，调用前必须选定：

- **单镜头局部换景**：只替换一个连续镜头里的天空、远景、地面或完整环境层。
- **全场景换景**：一个场景跨多个切镜，要求范围内每个镜头都属于同一个新环境。

同时选定一种变化语义：

- **纯视觉换景**：只替换环境身份与可见层，人物服装、动作、道具和事件完全沿用原片。
- **环境条件变化**：用户要的是实际存在的深雪、严寒、强风、低重力、泥泞或水下等条件，而不只是背景贴图。逐镜建立因果适配账本，记录 `新条件 / 失效的原假设 / 最小适配 / 保护项 / 时间范围`。

环境条件变化只允许调整让原事件继续成立所必需的部分，例如保暖功能层、步态与发力、脚底接触/足迹、衣发受风、呼吸、环境受光和环境声。人物身份、目标、关键事件、对象数量、镜头职责、切点、字幕、HUD 和节奏落点继续锁定；适配动作必须落在原事件的时间窗内，不得借机新增剧情或拉长等待。新条件没有实际影响到该镜头时，该镜头不做适配。

全场景换景不能把多镜头长视频只调用一次。模型常只修改首镜或某个显著镜头，导致旧背景在后续镜头重新出现。默认执行方式：

1. 按真实切点列出全部镜头和精确时间范围。
2. 为目标环境建立同一身份包：主视图，以及实际需要的反打、俯视、近景和室内外关系图。
3. 每个生成单元只处理一个镜头，并把目标镜头放在参考视频开头；短镜头向后补足调用时长，最终只裁回目标镜头范围。
4. 每镜使用同一环境身份包，逐项描述该机位可见的天空、地面、水体、远景地标、中景结构、天气和环境光。
5. 每镜独立审查旧环境残留，再按原切点、原顺序和原时长回装。

### 环境连续性合同

- 同一地标在不同机位的方向、距离和尺度可互相解释。
- 地平线、透视消失点、地面或水面高度与原角色脚底和道具接触保持一致。
- 天气、昼夜、主辅色、阴影方向和环境光在所有镜头连续。
- 环境替换不删除原动态对象。纯视觉换景不改变人物、怪物、道具、动作、接触、字幕或 HUD；环境条件变化只执行账本中已证明的最小适配。
- 近景遮挡按原镜头保留；目标环境图中的空前景只是构图留白，不代表清空原片前景。
- 范围内任何一个镜头显示旧天空、旧地面、旧建筑或旧山体，都算该镜头未覆盖。

### 单镜头环境提示模板

```text
编辑指令：替换视频1本生成单元内所有可见环境层，使本镜头完整发生在图1代表的［目标环境］。

本镜头必须替换：［天空］、［远景地标］、［中景结构］、［地面/水体］、［天气与环境光］。这些层共同属于同一个目标环境，不得保留源环境的［旧山体/旧城市/旧天空/旧地面］。

保持不变：视频1的镜头时长、机位、景别、运镜、人物身份、目标、关键事件、对象数量、遮挡顺序、字幕和 HUD。纯视觉换景时动作和接触全部保持；目标图只控制环境身份，不删除原动态对象。

因果适配：［若为环境条件变化，逐项填写“新条件 → 失效原假设 → 最小服装/动作/接触/受光/声音适配 → 保护项”，并限定在原事件时间窗；纯视觉换景写“不适用”］。

融合：目标环境匹配原镜头透视、地平线、景深、遮挡和主体受光；人物脚底、道具支撑面和水面接触不变；使用全片统一的［天气/昼夜/调色/主光方向］。

禁止：不得保留任何可见旧环境，不得改人物、剧情、动作、切点、文字或 UI，不得用叠化、模糊或裁切遮住未替换区域。
```

### 全场景覆盖检查

- 每个源镜头都有唯一 `shot_id`、输入范围、目标环境参考、输出文件和审查结论。
- 环境条件变化的每项联动都有因果适配账本；账本外人物、动作、道具、文字或节奏变化均按污染处理。
- 全部镜头通过后才能声明全场景完成；成功镜头数除以范围内总镜头数必须为 `100%`。
- 失败只返工对应镜头。不得因为首镜效果好而重复重生整段，也不得用部分成功版本进入终片。

## 商品替换

### 输入门槛

- 必须实际传入原视频和清晰目标商品图。
- 优先选择结构同类商品：泵瓶换泵瓶、软管换软管、罐装换罐装。
- 若原动作依赖源商品独有结构，而目标商品不存在该结构，例如按压泵换成旋盖瓶，必须阻塞该片段或改选不发生操作的镜头；不得让目标商品凭空保留错误机构。
- 目标商品图至少能确定轮廓、尺寸比例、开合结构、出料口、主材质、主色和品牌正面。

### 商品物理合同

- 原商品中心、底面、握持点、支撑面和运动路径不变。
- 替换后按目标商品真实长宽比缩放；底部落在原支撑面，不悬浮、不穿台面。
- 手指围绕目标商品真实握持区域，掌心和指节受力合理；手指不穿瓶、不多指、不复制手。
- 按压、旋拧、倾倒、挤压、揭膜等动作只能使用目标商品真实存在的机构。
- 出料从真实出口产生，方向由出口朝向、重力和施力决定；料体不会穿过包装、凭空出现或逆重力流动。
- 目标商品受现场光线影响，但固有色、透明度、金属/塑料/玻璃材质不能被改成源商品。
- 接触阴影、镜面反射、运动模糊和遮挡顺序跟随原视频。

### 商品文字合同

- 包装上的品牌与核心产品名由目标商品图负责，不要求模型重写密集小字。
- 原视频中的营销花字默认保留版式、出现节奏、位置、动效和层级。
- 仅当商品替换导致原花字事实错误时，替换对应短句；逐字给出新文本。其他花字保持不变。
- 不把商品包装文字和屏幕花字混为一层，不把包装上的小字放大成新花字。

### 商品替换提示模板

```text
编辑指令：只把视频1中的［源商品］替换为图1中的［目标商品］。

保持不变：视频1的总时长、画幅、全部镜头和切点；商品中心位置、占屏比例、运动路径；手部动作、握持时机、支撑台面、背景、光线、其他物体；原花字的版式、位置、动效与出现节奏。除下方明确列出的产品相关短句外，其他文字不变。

替换与物理适配：目标商品严格使用图1的轮廓、长宽比、［泵头/旋盖/喷嘴］、主材质、主色和品牌正面。底部始终接触原台面；手指改为握住目标商品的真实握持区；［具体操作］只作用于目标商品真实机构；［料体］从真实出口产生并受重力影响。匹配原片透视、受光、阴影、遮挡和运动模糊。

文字替换：把原花字［旧短句］替换为逐字［新短句］，保持原位置、字号层级、颜色和出现时机。包装密集小字不重写。

禁止：不得改变人物、场景、镜头、节奏和动作；不得新增或复制商品；不得改变包装结构；不得出现悬浮、穿模、错误握持、错误出料口或无关文字。
```

## 人物替换

### 输入门槛

- 必须实际传入原视频和获授权的目标人物参考。
- 目标人物体型和原动作空间明显不兼容时，先裁出更短原子动作或改选镜头，不能靠 prompt 强行挤入。
- 原片多人时明确替换哪一位，使用位置、服装或动作称呼，不只写“主角”。

### 人物物理合同

- 只替换身份外观：脸、发型、肤色、体型和服装；姿态、骨架运动、行走路线、速度、朝向、视线、手势与表演节拍来自原视频。
- 脚底接触地面，重心跟随迈步；坐姿接触座面；拿取时手指接触真实握持点。
- 与商品、武器、工具、其他人物的接触时机和遮挡顺序保持不变。
- 目标服装按惯性、风和身体动作自然随动，不穿过肢体或道具。
- 不新增替身、旁观者或第二张脸；不把背景人物一起换掉。

### 人物替换提示模板

```text
编辑指令：只把视频1中位于［位置］、执行［动作］的［源人物］替换为图1中的目标人物。

保持不变：视频1的时长、镜头、切点、人物骨架动作、移动路径、速度、朝向、视线、表情节拍、手势、与道具/地面的接触、背景、其他人物、声音和全部屏幕文字。

替换与物理适配：目标人物只继承图1的脸、发型、肤色、体型和服装；按照原人物姿态逐帧运动。脚底、座面、手掌和道具接触点真实；服装和头发由原动作惯性自然带动；匹配原片光线、透视、遮挡和运动模糊。

禁止：不得改动作、改机位、改节奏、换背景、增删人物、改变道具或重写文字；不得双脸、多肢、穿模、滑步或悬浮。
```

## 玩法替换

“只换玩法”把玩法规则视为唯一主变量，不是只换角色皮肤，也不是自由重写整片。人物身份与外观、背景身份与美术、镜头职责、切点、总时长和节奏骨架保持；为使新规则成立，允许完整替换以下闭环：

`玩家输入/自动触发 → 角色或装置动作 → 路径与接触 → 反馈 → 对象/资源状态 → HUD/数字 → 对应声音 → 下一目标`

先做节拍映射，每个源节拍只对应一个新玩法职责：

| 源时间窗与功能 | 新输入 | 新动作/路径 | 新接触与反馈 | 新状态/UI/声音 | 保持项 |
|---|---|---|---|---|---|
| 例如一次攻击反馈 | 已确认输入 | 同时间窗内的新规则动作 | 可见接触与反馈 | 有依据的状态变化 | 人物、背景、镜头、反馈密度 |

规则：

- 新玩法动作必须由新输入或自动触发产生，不能只换特效名；每次结果都有可见路径、接触、反馈和稳定状态。
- 角色为了执行新玩法可以改肢体动作和持有的功能道具，但身份、脸、服装设计与非玩法表演不变。功能道具变化仅限新规则必需项。
- 地图中的交互物、资源和局部玩法标记可按新规则变化；背景地标、天气、昼夜、整体材质与调色不变。
- HUD 只改与新玩法直接相关的按钮、资源、数值和提示，品牌区、固定版式和无关文字不变。没有数值依据时只写变化方向，不编造余额。
- 继承原片的首个有效动作时刻、反馈密度、爆发区间和最大空窗。新玩法动作耗时不同，可在同一节拍内重新分配起势/接触时间，但不靠增加等待或删除反馈改变节奏。
- 玩法版本直接从原母片派生；不得从角色版或背景版继续加工。

### 玩法替换提示模板

```text
编辑指令：只把视频1中的［源玩法］替换为［目标玩法］，人物身份与背景身份保持不变。

保持不变：视频1的总时长、画幅、镜头职责、机位、切点、人物脸/体型/服装、背景地标/天气/调色、非玩法文字，以及首个动作时刻、反馈密度、爆发区间和最大空窗。

玩法闭环：［输入/自动触发］→［起势与路径］→［接触对象］→［视觉/声音反馈］→［资源或对象状态］→［HUD变化］→［下一目标］。每一步绑定源片对应时间窗，不提前显示结果。

允许的因果适配：只改执行新玩法所需的肢体动作、功能道具、交互物、资源、玩法 HUD 和事件音效。未列出的角色外观、背景、镜头、字幕和事件不得变化。

禁止：不得顺手换角色、换背景、改画风、改故事目标、增删无关单位、虚构余额，或用粒子替代真实接触与状态变化。
```

## 游戏角色换皮

- 原视频固定保留地图拓扑、相机、玩家输入、单位数量、敌我关系、路线、攻击起势、弹道、命中点、受击反馈、资源变化、HUD 与数字变化。
- 目标图只替换指定角色/单位的模型、材质、服装和武器外观。
- 新武器必须与原武器功能同构。弓换弓、枪换枪；若功能不同，不能复用原弹道动作。
- 新角色脚底、格位和碰撞盒与原单位对齐；体型变化时只做等比例适配，不改变地图尺度、移动距离和命中时刻。
- UI 与世界对象分层：角色换皮不重画 HUD，HUD 不跟随相机或角色漂移。
- 金币、血量、伤害数字和升级反馈只能在原事件发生后变化，不提前、不重复、不倒退。

### 游戏换皮提示模板

```text
编辑指令：只把视频1中的［玩家角色/指定单位］替换为图1中的［目标角色］。

保持不变：原片全部镜头与时长；地图、道路、建筑、敌人、单位数量、HUD；角色起点终点、移动路径和速度；攻击起势、武器轨迹、命中点、反馈时机、资源及数字变化。

替换与物理适配：目标角色使用图1的轮廓、比例、服装、材质与同构武器；脚底/格位/碰撞位置与原角色对齐；左右手握持正确，武器从真实握点运动，攻击反馈仍发生在原命中点。匹配原片光照、阴影、遮挡和运动模糊。

禁止：不得改地图、镜头、玩法、敌我关系、HUD、数字、攻击次数和节奏；不得新增单位、复制角色、滑步、穿地、穿模、武器脱手或提前反馈。
```

## 退出 replacement-only 的条件

仅当用户明确要求下列剧情变化时，才退出本文件前面的“动作全部保持”模板；不能为了适配一个新外观而自行改变角色关系：

- 敌人改为朋友、宠物或救援者。
- 攻击改为送礼、贴贴、载乘、合作或治疗。
- 失败改为成功、逃跑改为同行、抢夺改为主动交付。
- 角色目标、阵营、情绪动机或事件结果发生变化。

此时先建立动作失效表：

| 原剧情事实 | 依赖它的旧动作 | 处理 | 新动作 |
|---|---|---|---|
| 巨兽具有攻击性 | 后退、踢击、受击、逃跑 | 全部替换 | 放下戒备、接近、贴贴、接受礼物、共同离开 |

处理规则：

- 旧动作只要与新意图冲突，就不能因为存在于动态参考中而保留。
- 新剧情必须显示新的起势、路径、接触、对方反应和稳定结果；不能硬切跳过关键互动。
- 原视频可继续提供角色身份、画风、场景基础、镜头速度和切镜密度，但不再独占动作和事件顺序。
- 逐字字幕、对白、表情和音效随新因果链更新；固定免责声明和无关 HUD 才继续保留。
