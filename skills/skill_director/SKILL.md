# Skill · 编导转译

## 执行合同

- 输入：已定稿剧本、用户目标、可信参考和现有计划。
- 输出：符合 `vibefilming.director-plan/v1` 中立合同的 `director_plan.json`，或只更新
  审查问题涉及的部分。
- 合同只固定跨阶段语义：`contract`、逻辑生成单元、开始/结束状态、参考职责、
  `composition.transitions` 和最终采用顺序；各专业 Skill 可增加自己的命名空间，
  但不得改名或移动这些稳定字段。
- 不写执行模式、审批状态、工具调用参数或其他 Skill 的工作说明。

## 每次执行只做这 5 步

1. 校准剧本、用户要求、参考素材和现有计划；先列“允许改变／必须保持／因果适配闭包”。每项适配必须写清“新条件 → 失效的原假设 → 最小适配 → 仍锁定内容”，发现无因果证据的越权改动先移除。
2. 写清一句话主线，以及每段推进什么。
3. 把每段拆成可见的镜头节拍、时间变化和首尾状态。
4. 登记本段真正需要的角色、场景、道具、状态、关键帧和声音。
5. 检查时长、资产、连续性、文字和声音职责是否可执行。

原位编辑时由原视频锁事件；结构重建时逐镜重建来源事件，保留动作拓扑、数量、接触、镜头职责和时间落点，但不承诺逐帧轨迹。角色替换只做接触适配；玩法替换只重建规则所需的操作到反馈链；换环境只有在真实物理条件改变时才能做已登记的最小服装/动作联动。切鱼不得改砸石，二合一不得改三合一；只有获准改剧情时才重写事件。

## `director_plan` 最低合同

`contract` 固定为 `vibefilming.director-plan/v1`，并表达以下语义：

- 全片主线、风格和目标时长。
- 每段的功能、时长、镜头、动作节拍、文字、声音、开始状态和结束状态。
- 每项参考素材负责锁什么，不继承什么；单变量复刻保留原片全部未点名内容，新资产只为替换目标制作，不重新设计全套角色、场景或故事板。
- 每个逻辑视频生成单元的 `storyboard_plan`：建议面板数、相对时间点、必须画出的初始姿态/路径/接触/反馈/落点，以及主体运动、受力和摄影机箭头职责。短动作单元按内容使用 3–6 格，长单元最多 9 格，不机械固定九宫格。
- 人物、道具、空间、方向和状态如何跨段连续。
- 哪些片段是最终采用版本，以及合成顺序。

完整母片单变量 `edit_in_place` 还必须同时规划 `generation_units.json`：

- 只把 `full_timeline.json` 中相邻且 `affected=true` 的范围编为单元；
  `affected=false` 不建立生成单元，按原起止直接复用。
- 每个单元记录精确 `source_range`、涉及的 `shot_id`、原切点、目标替换、必须保持、
  首尾状态、最终回装范围和原音轨职责。动态参考总长硬上限为 15 秒，即使当前模型
  capability 支持更长；不得跨原切点合并，超长沿真实切点拆分。
- 每个单元登记精确源段裁切、私有参考 sidecar、故事板图片/JSON、请求绑定证据、
  首次任务、可选定向修复任务和终版片段；占位文件不得标为就绪。
- `composition` 明确按完整源片顺序混排复用段与生成段，原切点不因模型单元边界改变。

正式视频段只按当前执行能力返回的模型 capability 合同规划；短信息点作为段内节拍，
不在本 Skill 复制提供方时长、格式或参考数量限制，也不为满足模型限制改写原始参考
的镜头结构。

## 游戏编导重点

只保留以下判断，不发明游戏专用参数：

- 先区分原位编辑、结构重建或生成式重制。结构重建需为每镜规划动作前/后源帧、身份参考、目标变量参考和完整动作链；玩法替换只改输入、动作、接触、反馈、资源/UI/声音的必要闭环，人物与背景身份按保留稿重建。
- 原位编辑中原视频负责操作、镜头、事件顺序和数量变化；生成式重制中新剧本负责这些事实，原视频只提供已选中的节奏、构图、画风或镜头功能。需要原片驱动时仍须确认视频输入可访问，否则不承诺原运动保真。
- 中段完整帧可以作为设计锚点，但不能擅自变成开场。空环境图也不代表删除画外或动态对象。
- 保留目标、操作、反馈、资源收支和升级的因果。只知道消耗量时不猜起止余额。
- 建筑建成、升级完成、全局昼夜和局部灯光分别规划。再入画才看到灯亮时，不反推画外触发时刻。
- 保留原有固定、跟随或拉远方式，以及地图拓扑、地标、敌我方向和操作区域。
- 区分世界对象、随对象移动的标签和固定屏幕 UI；数字、按钮和字幕默认安排原生生成，写清可读范围与验收标准。
- 玩法转绘先选择能覆盖主要风险的已有片段做验证，不额外制造一套审批流程。

## 游戏场面合同

每个游戏生成单元都要把下列内容设计到可拍，不能只写玩法摘要：

### 场面构成

- 地图/棋盘边界、道路、格位、平台、入口出口和固定地标。
- 玩家角色、敌人、NPC、建筑、资源、交互区和障碍物的初始位置、朝向、数量与层级。
- 前中后景分别承载什么，主体占画面多少，哪些区域必须始终可读。
- 固定 HUD、世界标签、教学手势和特效的图层关系；UI 不跟随世界镜头漂移。

场面不是资产清单的堆叠。要明确谁在场、谁暂时画外、谁会再入画，以及新对象第一次出现时采用什么设计。

### 画风合同

游戏画风至少固定：

- 2D/2.5D/3D 与写实程度。
- 人物比例、轮廓语言、建筑与道具造型规则。
- 材质粗糙度、反光、边缘、纹理密度和特效形状语言。
- 主色、辅色、点缀色、饱和度、对比度、阴影和全局昼夜。
- 哪些固有色不能被灯光误改，哪些颜色变化属于玩法反馈。

“保持原画风”不是合同。要把可观察特征写出来；参考图只锁它真实展示的部分。复刻默认锁定来源媒介与写实程度：写实不能变塑料 3D、游戏 CG 或动画脸，3D 不能变真人实拍，2D/像素/黏土等也不能跨媒介；只换人物、场景、产品或玩法时，`style_contract` 继承来源媒介并排除互斥媒介，只有用户明确授权改画风才允许重写。

### 动作与运动合同

每个关键动作写成：

`起始姿态/位置 → 输入或自动触发 → 起势 → 运动路径 → 接触/命中 → 反馈 → 落点与稳定状态`

同时写清：

- 主体移动方向、速度变化、重心和停止位置。
- 左右肢体、武器/工具、弹道、掉落物和交互区的关系。
- 头发、衣摆、武器拖尾、资源吸附等次级运动。
- 镜头是固定、跟随、平移、推进、拉远还是旋转；何时开始和结束。
- 动作必须在一个镜头内连续完成，还是允许用明确切点跨镜头。

不允许用“角色完成攻击”“顺畅走过去”“升级动画出现”替代机械动作。原位编辑保留原片运动；结构重建复刻动作拓扑与时间落点；生成式重制按新剧本重建动作。

### 速度合同

参考复刻时，逐项继承拆片测得的速度证据，不能把它们改写成“快速、流畅、节奏紧凑”等形容词：

- 首个有效玩法动作的最晚发生时刻。
- 主体每次移动的跨屏比例、目标耗时和允许偏差；分别规定常规移动、冲锋、飞行、吸附等状态。
- 瞄准、起势、攻击、命中、拾取、交付、建造或升级各自耗时。
- 单点与多点并发的攻击/命中频率、常规反馈间隔和爆发反馈间隔。
- 操作停顿、观战、转场、收尾及战斗期的最大无反馈空窗。
- 镜头跟随或平移的跨屏比例、耗时和方向；原片固定镜头时保持固定。

每个生成单元只选择原片中同类动作的速度基线。例如战斗冲锋可继承战斗冲锋速度，经营角色搬运应继承经营走路速度。若原片测量值缺失，保留为待测，不凭品类常识补数。

提速优先压缩无意义停顿、提高位移/攻击/反馈速度，并保持完整的“起势→接触→反馈→状态后”。不得仅缩短成片时长、删除因果环节，或在同一生成单元增加更多独立状态转移。

原位编辑用动态参考校验速度；结构重建可以使用静态状态帧，但必须把拆镜测量编进动作链，并明确只承诺节奏落点和拓扑近似，不承诺逐帧轨迹。

### 特效与反馈合同

每个玩法特效都要绑定事件：

- 瞄准/预警：出现位置、方向、持续时间和消失条件。
- 发射/移动：弹道、拖尾、速度和与主体动作的同步。
- 命中/受击：接触点、闪光、震动、击退、血条或状态变化。
- 掉落/收集：从哪里产生、落点、吸附路径、进入哪个资源槽。
- 建造/升级：投入先发生，结构如何建立，完成后哪些外观和能力持续保留。

装饰粒子只能增强已经成立的反馈，不能代替命中、收支、升级或完成状态。

### 段内时间轴

4–8 秒通常承载一个完整原子动作或两个强关联动作；9–15 秒可承载 3–6 个阶段，但每个阶段都要有足够可见时间。复杂循环优先拆成多个可审单元，不把“采集→加工→售卖→升级→自动化”压进一个模型调用。

每个阶段至少写：

- 当前场面状态。
- 主体和副主体运动。
- 镜头与焦点变化。
- 特效、UI、资源和声音反馈。
- 本阶段继承的位移速度、动作耗时、反馈间隔和最大空窗。
- 本阶段结束后不可回退的状态。

### 连续性账本

逐段维护：

- 人物/敌人/NPC：位置、朝向、数量、身份和画内/画外状态。
- 建筑/道具：存在、等级、损坏、亮灯、持有者和再入画状态。
- 资源：来源、变化量、去向；没有完整数字证据时不造余额。
- 场景：地图拓扑、地标、昼夜、天气和局部灯光。
- 镜头/UI：相机位置、运动方向、HUD 锚点和内容状态。

### 全场景环境覆盖账本
用户要求连续场景从头到尾换背景时，计划必须覆盖范围内每个真实镜头，不能只写一个整段目标：
- 列出 `shot_id / source_range / 机位 / 景别 / 可见环境层 / 目标环境参考 / 终版文件 / 审查状态`。
- 场景范围以叙事空间为单位，可以跨多个切镜；切到近景、反打或俯视不代表环境替换暂停。
- 每个镜头默认成为独立生成单元。短于模型最小时长的镜头向后保留生成把手，但终版只使用原镜头精确范围。
- 所有镜头共享同一环境身份、地标布局、昼夜、天气、调色和主光方向；机位无法由主环境图支持时，先规划同一环境的对应视图。
- 纯视觉环境变化只改空间外观；真实环境条件变化可逐镜登记保暖层、步态/发力、足迹、风力反应、受光和环境声的因果适配。身份、目标、关键事件、数量、字幕、HUD、切点、镜头时长与节奏落点仍为保留项。
- 合成顺序和切点沿用原片；只有所有范围内镜头的旧环境残留均为零，场景覆盖状态才能标完成。
计划不得把“整段调用一次”当作全场景覆盖方案。多镜头单次编辑仅可作为能力试验；出现只改首镜或局部镜头后，正式方案必须切回逐镜生成和回装。

### 剧情变化与动作失效表
角色关系、意图、阵营、事件性质或结果变化时，先重建因果，再设计镜头。计划必须登记：
- 新剧情前提、新目标，以及原片每个关键动作依赖的旧前提。
- 每个旧动作是 `保留 / 替换 / 删除`。
- 替换后的新动作链、接触方式、双方反应和稳定结果。
- 随剧情变化的表情、字幕、对白、音效和 UI；无关固定层才保留。
只要旧动作与新设定冲突，就自动失效。例如巨兽从攻击者改成友善同伴时，踢击、格挡、逃跑、受击和伤害反馈必须删除或替换为警惕解除、接近、贴贴、递送、抚摸、登乘或共同离开。不能在计划里同时写“友善”与“保留原攻击动作”。
新互动按机械过程设计：`发现 → 判断意图 → 主动靠近/示意 → 接触建立 → 对方响应 → 共同动作 → 可见结果`。
关键接触不得靠硬切跳过。若时长不足，减少独立事件或拆成连续生成单元，不删除接触与反馈。高节奏通过压缩等待、提高反馈频率实现，前 `1–2 秒`给出核心事件，不用省略因果来提速。

## 参考与连续性经验

给每项参考一个单一职责：

- 原位编辑由原片负责动作与事件；结构重建由保留稿、源状态帧和速度证据共同负责；生成式重制由新剧本负责。
- 角色或产品图负责身份与固有外观。
- 环境图负责空间外观，不负责决定动态对象是否存在。
- 状态图只负责稳定的动作前或动作后结果，不用对象悬空、转化中、数量未收敛或机位变化中的瞬时帧重演过程。
- 故事板负责本生成单元几秒内的事件流动和局部动作拓扑，可用简笔人物、时间标签、动作/受力/摄影机箭头表示起势、路径、接触、反馈与落点；不负责精确材质、逐字文字、成片画风或镜头数量。穿越整场景的长距离路线仍由 route map 负责。

参考之间冲突时，先服从用户明确锁定的事实，再服从原始动作和事件，最后才是风格与构图建议。不能把多个互斥要求一起交给生成模型碰运气。

连续性优先追踪四条线：
1. 人物和敌我的位置、方向与数量。
2. 关键道具、资源和建筑的持有或存在状态。
3. 昼夜、天气、损坏、升级等可见状态。
4. 镜头、地图地标和屏幕 UI 的坐标关系。
除完整母片单变量编辑的 15 秒硬上限外，同机位同场景且总时长不超过当前 capability
的单次上限时，连续表演优先合成一个
生成单元，减少接缝；超过上限且当前 capability 支持延长、同时仍是一镜到底时，
才用上一段完整视频串行续写。普通切镜只做状态对齐，不能为了“更一致”把全片串成
不可并行的长链。
每个切点明确选择硬切、叠化或其他效果，并写出理由及重叠秒数。叠化会缩短总片长，重叠区不要安排新台词、关键字幕、奖励或数量变化；连续动作优先动作匹配，不能用叠化掩盖人物跳位。相邻段的首尾状态需真正接得上。
### 切点分类与接缝合同
- `same_scene_continuous` 先判是否同一长镜头：是则用上一段完整视频 `extend`；不是且必须串行时，若下段不需要其他参考，可提取左段真实末帧作严格 `first_frame`，终态固定时再加同画幅 `last_frame`；若角色/环境/故事板参考不可缺，则末帧只能作为 `reference_image` 软锚点。保持位置/尺度/姿态/动作相位/道具/UI/光线/镜头速度并按 `match_cut` 合成，禁止用特效遮错。
- `same_scene_elliptical` 必须让跳时或省略可读；`scene_change` 必须规划有画面来源的遮挡、风雪、浪花、烟尘、闪光等视觉桥，在上段进入并达峰值、下段从同状态开始且 `0.20–0.50 秒`内清除，无共享桥时才用短后期转场。
- 每项登记 `cut_class / left_end_state / right_start_state / continuity_anchors / generation_overlap_s / visual_bridge / effect_source / effect_peak / effect_clear / audio_handling / seam_review / fallback`；详细设计按本目录手册“七、段间承接、转场和剪辑”执行。
原片只换商品、人物或环境的复刻任务额外遵守：

- 原片本来存在的硬切、闪切、淡入淡出和声音桥原样保留，不为了“更丝滑”另加转场。
- 因生成时长上限而在同一原镜头内拆段时，优先选择动作完成后的稳定帧，并用上一段完整终版视频延长；只有非长镜头但必须等待上段结果的同场景新段才考虑严格首帧。相邻单元保留 `0.15–0.30 秒`把手，合成按 `match_cut` 硬切。
- 手、商品、液体、数量变化或字幕正在运动时禁止用叠化掩盖接缝，否则会出现双手、双商品、半透明穿模和重复文字。只有接缝两侧主体静止、无关键文字且业务允许改变原剪辑时，才可把 `0.12–0.20 秒`短叠化作为验证失败后的备用方案。
- 严格复刻默认关闭分段生成音频，最终回铺完整原片音轨；这样人工拆段不会制造口播重音、断句或 BGM 抽吸。若产品事实必须改写，声音与文字应作为另一个明确变量处理，不能夹在“只换商品”里静默修改。
- `director_plan.composition.transitions` 每项记录 `at`、`type`、`cut_class`、`source_time_s`、`reason`、`continuity_anchors`、`visual_bridge`、`audio_handling`；模型拆段还记录 `generation_overlap_s`、`seam_review` 和备用方案。最终 `.timeline.json` 必须保留这些依据。

复用同一张清晰主场景参考建立各机位；只锁参考确实展示的内容。环境色彩可来自目标风格板，玩法标识与 HUD 固有色按原片或明确目标保持，不受氛围光误染。

字幕允许逐句生成，默认由 Seedance 完成。写清中文逐字内容、出现与消失时间、位置和样式；长句拆成可读短句，不设强制字幕覆盖率。

## 常见 bad case

- 计划写“保持一致”却没有保留表；只换背景却重新设计人物、字幕或剧情，只换人物却重建场景。
- 中段锚点包含已建建筑，下游误把建筑放到开场。
- 环境参考没有角色，下游因此删除角色和塔。
- 整个场景要求换背景，却只规划一次多镜头调用；首镜换成功、后续镜头恢复旧环境。
- 每个镜头各自生成新背景，但没有共享环境地标、天气和主光，导致切镜后像换了另一个地点。
- 把敌对巨兽改为友善伙伴后仍保留原踢击、逃跑和受击反馈，剧情设定与人物行为冲突。
- 新剧情只写“成为朋友”或“成功获救”，没有靠近、接触、双方反应和稳定结果。
- 为了电影感把原玩法跟随镜头改成环绕、浅景深或固定机位。
- 每段都要求完整资产包，模型把多视角角色误生成人群。
- 局部文字错误却重做整段，丢掉原本正确的动作和资产。

## 电商编导重点

- 每段承担钩子、产品识别、痛点、使用、证明、结果或行动中的明确职责。
- 产品、包装和 Logo 必须有真实参考；证明镜头不改变产品、主体或对比条件。
- 人物动作符合真实使用场景，口播与产品动作同步。
- 直播场景要有合理营业信息密度，但产品仍是第一视觉中心。

## 口播、情绪与节奏账本

有口播或人物表演要求时，计划逐句记录 `line_id / speaker / text / start / end /
voice_mode / visible_speaker / emotion_trigger / expression / gesture / voice_delivery`。
选择原声保留、原生对白或画外旁白之一；画外旁白不强制口型，可见说话者才核对口型。
必说句覆盖率目标为100%，分段边界不得切掉词、末字或吸气；句末留可听完的余量。
无口播任务记N/A，不能对纯玩法套覆盖率。

情绪按“触发前状态→触发→眼神/眉眼→身体反应→声线变化→稳定结果”安排，
每个变化明确时刻和可观察证据；重要表情用足够人物占比和可见脸部，
不要让快速镜头、遮挡或全景使表演不可读。

新创高节奏短片没有母片测量时，明确这是设计目标而非来源事实：
首个有效事件1–2秒内；相邻主要反馈通常间隔1–2秒；超过1秒的静止等待
必须有口播信息、反应或产品证明职责。复刻仍继承母片测量，不用这些默认值覆盖原片。
动作与台词并行时检查理解负荷，不能靠堆更多事件解决节奏慢。

资产计划分别标记“需要生成”与“已就绪”；已就绪引用工具返回的真实路径，
不得把逻辑资产名转换成猜测文件名。生成结果回填后才允许下游消费。

## 硬门禁

- 没有主线或段落职责。
- 只有文学描述，没有可执行节拍和状态变化。
- 游戏关键段没有场面清单、画风合同、动作机械过程、特效职责或连续性账本。
- 原片复刻只有“快、紧凑、流畅”等形容词，没有可执行的位移、动作、频率或空窗数值。
- 原位编辑要求具体运动却未传对应视频；结构重建缺动作前后状态或机械动作链；或生成式重制仍让旧动作覆盖新剧本。
- 一个生成单元塞入过多独立状态转移，导致任一关键因果没有可见时间。
- 动作生成单元没有可执行的 `storyboard_plan`，或计划未覆盖起势、运动路径、接触/命中、反馈和稳定结果。
- 主要主体或关键状态只靠文字，没有真实参考。
- 参考职责互相冲突，或同一对象同时要求保留和替换。
- 全场景换背景没有逐镜覆盖账本、统一环境身份包或原切点回装方案。
- 剧情前提变化后没有动作失效表，仍保留与新意图冲突的攻击、躲避、受击或逃跑。
- 新剧情关键接触被硬切省略，只显示已经和解、已经登乘或已经获救的结果。
- 相邻段的位置、方向、道具或状态无法承接。
- 关键文字和声音没有明确执行方式。
- 计划写了不存在的素材，或用“保持一致”“电影感”代替具体决定。
