# Skill · 制作总控

## 唯一职责

本 Skill 只回答五件事：

1. 当前处于哪个阶段。
2. 当前阶段需要什么产物。
3. 是否允许进入下一阶段。
4. 失败应回到哪个责任环节。
5. 最终交付是否完整。

不在这里重复剧本、镜头、提示词或审查标准。专业判断由当前任务直接命中的专业 Skill 独立完成；不得要求一个 Skill 再读取另一个 Skill。

## 流程

项目沿用七个状态阶段：

`breakdown → story → entity → asset → animate → compose → review`

- 没有参考视频时可跳过 `breakdown`。
- 阶段可以因审查问题回退，但不能跳过当前产物需要的前置事实。
- 每轮只推进一个当前阶段；阶段完成后再更新状态。
- `manifest.json` 记录阶段与执行模式；`director_plan.json` 按
  `vibefilming.director-plan/v1` 中立合同记录当前成片计划和终版段。Skill 只消费
  合同字段，不依赖产物由哪个 Skill 创建。
- 不靠聊天摘要、目录扫描或文件名猜状态。

## 完整母片单变量默认合同

用户上传一个母片并用自然语言要求“完整复刻、只改一个变量、其他保持”时，自动执行
下列内部合同；不得要求用户补路径、工具名、模型字段、文件名或制作步骤：

- `full_timeline.json` 从 `00:00` 连续覆盖到源片末帧。每个真实镜头或段落记录精确
  起止、原切点、媒介类型、人物、动作、相机、玩法因果、字幕/HUD、音频职责，以及
  `affected=true|false` 和可核验理由；不得只挑代表段。
- 真人实拍、可识别人脸或疑似真人肖像一律 `affected=false`，不得进入抽脸、参考发布
  或生成链路，终版按原起止范围直接复用源片。只有明确非真人、卡通、游戏或风格化，
  且确受唯一变量影响的连续范围才可生成。
- `generation_units.json` 只包含连续的 `affected=true` 范围。每个动态参考总长不超过
  15 秒，不跨原切点合并；超长沿真实切点拆分。每个单元在首次生成前已有正式脚本职责、
  编导计划、低保真动作故事板图片与 JSON，并记录故事板真实绑定证据。
- 每个单元先在当前项目裁出精确源段，再通过当前参考发布能力取得私有 sidecar，随后使用
  Seedance 2.5 `edit`。每个稳定 `unit_id` 最多首次提交加一次基于明确审片证据的定向
  修复；查询、下载或同步失败不得重做。
- 最终以完整源片为时间轴：`affected=false` 原样复用，仅在原起止范围替换生成单元；
  锁定原顺序、切点、反馈间隔、最大无反馈空窗、画幅、分辨率、字幕/HUD 时机和完整
  原音轨。只允许为精确贴合区间做不超过 2% 的微调速，不删动作、不加等待或慢动作凑时长。
- 成片与源片时长误差不超过一帧。终审覆盖全片解码、首尾、内部切点、声音、字幕/HUD、
  唯一变量纯度、真人段复用和接缝证据。
- 项目交付至少包含可播放完整 MP4、`delivery_manifest.json`、
  `full_timeline.json`、`generation_units.json`、`review_final.json`、全片联系表及
  内部接缝证据。只有这些文件可下载且证据支持时才可 `passed`；否则如实
  `partial|blocked`，不得拿中间片段冒充完整成片。

## 复刻模式门禁

参考视频拆解完成后、正式剧本开始前，按用户授权范围确定模式；模型是否重新生成像素不决定创作权限：

- `edit_in_place`（复刻默认）：只改用户点名的对象或场景，其他内容全部保留；即使用模型重新生成整段，也不能扩展修改范围。
- `structural_remake`：用户明确不采用视频编辑，母片只在本地拆镜、测速和抽取状态帧；生成端按来源镜头逐镜重建，保留剧情、动作拓扑、数量关系、镜头职责、切点和时长，只重设计授权变量。不得宣称逐帧不变。
- `generative_remake`：仅在用户明确要求重写剧情或自由创作时启用；仍只改授权部分，不能由工具能力、改动数量或“更有爆款感”自动升级为全片重写。

模式及“允许改变／必须保持／因果适配闭包”写入项目状态。每项适配记录“新条件 → 失效的原假设 → 最小适配 → 仍锁定内容”；写不出完整链路就按未授权处理。只换角色时锁场景和玩法；只换玩法时锁人物与背景身份；换环境时纯视觉换景锁动作，真实条件变化才允许最小服装/动作联动。未点名的剧情、数量、镜头、切点、时长、画幅、字幕、HUD和节奏证据均保留。

- 原片媒介与质感默认属于“必须保持”：2D/2.5D/3D、真人实拍、写实 CG、
  卡通、像素、黏土等不能互换，写实程度、人物比例、材质与光照也不能因换人、
  换景或换玩法而漂移。只有用户明确授权“改成某种画风”才解除；否则媒介转换
  属于范围越权，直接回退到资产或提示环节。
- `edit_in_place` 可以让来源事件继续控制动作，只替换授权变量。
- `structural_remake` 由正式保留稿和编导计划控制动作；必须给每镜动作链、源状态帧职责和允许误差。它不需要把母片作为视频生成输入，但必须如实标记“结构重建”，不能用“其他像素不变”验收。
- `generative_remake` 在明确获准的剧情范围内另写 `script.md`；全新剧情授权才重建整条主线，只改局部关系时只重建受影响因果。单变量编辑的正式剧本是原事件的保留稿，不强迫编新故事。
- 新对象与原动作不兼容时先选择兼容外观；仍不兼容就报告具体冲突，不擅改动作。每个角色版、玩法版和环境版都独立从同一母片出发，不在任何裂变结果上叠加下一变量。
- `materials/script_from_breakdown.md` 永远只是来源观察稿。生成式重制中，正式 `script.md` 不存在、仍逐句复制来源剧情，或没有说明保留哪些复刻元素时，`story` 不得标为完成。
- 生成式重制的后续计划和提示词以正式新剧本为剧情事实源；原视频仅承担明确登记的节奏、构图、画风或动作参考职责，不能覆盖新剧本。

## 两种执行模式

- 开始生成前必须确定模式。已有项目沿用所选模式；明确要求端到端就直接写入，未选择时仅询问这一次。
- `autonomous`：拆镜和剧本通过机器校验后继续，不等待人工确认。缺不可替代输入、合规限制、提供方拒绝或定向修复仍失败时停止。
- `human_gated`：拆镜完成后暂停一次，剧本定稿后暂停一次；只有用户在后续消息明确确认才继续。
- 模式只影响是否暂停，不降低质量要求，不改变专业产物。
- 只有总控负责读写执行模式和审批状态。其他 Skill 只交付自己的结果，不复制这套状态逻辑。
- 调试 `stop_after` 始终优先，到点立即停止。

## 阶段门禁

- 路径与输入：保存真实 project_id/project_dir 和已就绪媒资引用；计划占位路径
  不可执行。生成/下载返回成功且文件存在后才更新可消费状态。失败回查原返回或素材索引，
  不猜路径、不重建项目、不用重复生成替代下载或发布恢复。
- 客户验收：有口播/情绪/节奏要求时分别登记验收维度；口播以实际听音或音频
  证据为准，缺听音能力不得写通过。生产阶段的“可播放”与整体合同通过分别报告。
- 拆镜：时间连续、来源范围明确，观察事实与推断分开。
- 剧本：正文已落盘，主线、因果、逐字声音内容和事实边界成立；生成式重制还必须完成复刻元素映射和全量新剧情。
- 编导：每段目标、节拍、参考职责、首尾状态和声音计划可执行。
- 资产：计划真正需要的参考已存在；用户素材只做技术校验，生成素材按风险审查。包含明显运动、接触或状态变化的每个逻辑视频生成单元，还必须有已落盘的动作故事板图片与同名 JSON；静态展示单元需记录免故事板理由。
- 生成：正式视频段必须符合当前执行能力返回的 capability 合同；读取计划产物中的
  `independent / video_extend / strict_first(_last) / multimodal_reference`
  策略并核对实际输入、时长、画幅、声音一致，不由总控重新选型。结构重建的源帧、
  目标变量参考和动作要求必须真实传入；动作单元的故事板必须作为真实参考图片参与
  调用，因此不得与互斥模式混用或为后者删故事板。
- 合成：只按计划中的终版段与顺序合成，明确传入每个切点的分类与转场；同场景先做接缝抽帧审查，跨场景核对生成式特效桥，再读取实际合成时间轴核对重叠和片长，不扫描目录猜版本。
- 审查：关键段按需审，完整成片只终审一次；业务未评价的主观项明确标为未验证。
- 代表段、能力试片或单原子片段只缩小 `script.md` 与 `director_plan.json` 的内容范围，不免除落盘；两者不存在时不得进入首次生成，也不得用拆镜草稿或阶段备注替代。

## 合成执行合同

进入 `compose` 后，总控只编排中立产物，不复制执行器命令：

1. 请求当前执行能力按计划裁切，并消费其媒体探测结果。
2. 为 `composition.transitions` 的每个切点请求接缝证据产物，再交给审查职责判定。
3. 只有接缝放行后才请求合成；硬切、转场和声音处理必须进入版本化 timeline 产物。
4. 最终消费探测、timeline、可解码抽帧和音轨状态，不能用“命令成功”代替成片合格。

具体工具名、参数和证据采集方式只属于当前执行器及其 schema；新增或替换执行器不要求修改总控。

## 游戏项目只加这四点

- 先区分剧情前贴、固定逻辑换皮、玩法转绘和生成式重制；后两者先验证一个能覆盖主要风险的代表段，再决定是否扩量。
- 先说清只换环境还是全视觉换皮；没有授权的角色、地图关系、UI 和玩法事件不得顺手改掉。
- 原位编辑中原视频负责动作与事件；结构重建由保留稿、拆镜测量和状态帧共同约束，只承诺动作拓扑与节奏落点；生成式重制由新剧本负责动作与事件。只有静态图时不能宣称逐帧复现原运动。
- 机器可检查硬伤，玩法手感、美术偏好和声音仍需真实业务反馈；三者不能互相代签。

## 返工编排

- 只消费执行器返回的版本化 runtime policy/status：根据当前阶段、允许动作、阻塞原因、
  未终结任务和剩余提交额度决定继续、等待或交付；不在总控复制分钟数、轮询间隔、
  重试次数、错误码分支或 CLI 子命令。
- 后期修复持续失败时写出残留偏差，不把“没有新增生成调用”当作无限后期额度。
  文字重绘、字幕补烧没有用户授权不能作为原生文字失败的隐式兜底。
- 原片出现明确隐私/内容策略拒绝，停止受阻范围，不轮换 edit/reference/auto/首尾帧碰运气，不另做概念片占用预算。只在用户授权变更目标后制作不同范围，并如实声明。
- 异步任务以执行器状态合同中的稳定 unit、task 和结果状态为准；普通硬切不强制串行，
  外部等待不重复提交。
- 先定位时间、区域、对象和根因，再修受影响的最小范围。
- 参考错先修参考，计划错先修计划，文字层错先修文字层；不原样重抽。
- 每次重做另存版本，不覆盖可回退版本。
- 只有 `vibefilming.generation-unit-status/v1` 表示 `can_submit` 时，才允许有依据的
  定向修复；阻塞后交付明确结论和最小补充项。总控不读取私有日志、不按文件名自行
  重算次数。
- 记录真实调用次数和可取得的成本；没有投放数据不声称转化提升。
- 参考链路故障按执行器返回的分类与允许动作恢复；核心原片被拒绝时停止，不通过删原片
  或减少参考图碰运气。
- 静态帧重建若已出现对象复制、数量漂移或机位跳变，判为输入能力阻塞，不再缩短 prompt 或继续抽卡；等待可访问的原片 URL，或把目标降为无动作的外观样片。

## 总控经验

- 计划很长不代表可以一次推进多个依赖阶段；先完成当前产物，再读取下一阶段需要的规则。
- 审查指出的是表面症状时，先追到根因，避免在生成端反复修本应由剧本、计划或素材解决的问题。
- 用户改方向时，先判断影响范围：全局风格变化通常影响全片，单个文字或资产错误通常只影响局部。
- 上游产物变化后，标记依赖它的计划、参考、视频、合成和审查结论为待更新；无关段继续复用。旧版“通过”不能为修改后的成片背书。
- 所有裂变项目先验证一个具有代表性的风险段，再批量生成同类变体；代表段必须覆盖本次真正要改变的对象和要保留的动作。
- 原生字幕与视频一同生成；不要另接烧字幕流程。文本修复若导致视频重新生成，按变化范围复核画面与衔接。
- 已有可靠产物优先复用；只补缺失信息，不为了“更完整”重跑耗时模型。
- 代表段通过只说明该方案在该范围可用，不自动证明全片、批量或投放效果。

常见流程事故包括：状态提前标完成、扫描目录混入旧版本、把策略跳过写成审查通过、人工模式预先批准、无人模式无理由停下，以及修复后覆盖唯一可回退版本。

## 最终交付

每阶段完成立即核验当前项目实际产物可访问，受阻和预算耗尽也必须交付材料。
交付清单必须声明 `contract: vibefilming.delivery-manifest/v1`，并包含
`status=passed|partial|blocked`、来源范围、目标达成/残留项、所选文件、未终结任务
和真实耗时；可用版本标为 `best_available`，概念样片标为 `concept`。只有全合同通过
才能叫最终成功，不把源片、未完成的全长回装或样片当整片复刻通过。发布方式由当前
执行能力负责，输出失败只能重试发布，不能重做视频。

完整母片单变量任务的清单还要记录源/成片精确时长、复用与生成区间、Seedance task
IDs、故事板绑定、每次提交与残留缺陷；`full_timeline.json`、
`generation_units.json` 和 `review_final.json` 分别使用
`vibefilming.full-timeline/v1`、`vibefilming.generation-units/v1` 和
`vibefilming.review-final/v1`。

交付时只汇总：

- 成片或当前可用产物。
- 各阶段真实状态。
- 机器制作结论、业务验收状态和投放验证状态。
- 未解决问题、影响范围与下一步最小动作。
