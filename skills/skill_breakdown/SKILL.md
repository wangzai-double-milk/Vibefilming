# Skill · 参考视频拆镜

## 职责

完整理解参考视频，产出：

- `materials/reference_breakdown.json`，顶层
  `contract: vibefilming.reference-breakdown/v1`
- `materials/拆片表.md`
- `materials/script_from_breakdown.md`
- 完整母片单变量复刻额外产出根目录 `full_timeline.json`，顶层
  `contract: vibefilming.full-timeline/v1`

JSON 是程序存储，Markdown 是人可读依据。本 Skill 只规定拆镜判断标准和产物质量，
不作为任何执行器的运行时依赖。多模态调用的机器格式由当前执行能力自己的版本化合同
负责；镜头信息与全局结构必须来自视频分析，不调用纯文本模型补充视觉事实。

## 拆解原则

1. 首镜从 `00:00` 开始，相邻时间严格相接，末镜覆盖完整分析范围。
2. 实际切镜与同镜头内的状态变化分开记录，不为凑时长虚构切镜。
3. 只写能从视频观察到的内容。数字、声音、触发时刻看不清就明确未知。
4. 原始镜头可以长于模型生成上限；拆镜不为了下游调用限制篡改原时间轴。
5. 用户提供的标注是辅助证据，与视频冲突时以可观察画面为准并指出冲突。
6. 用户只换场景或人物时，完整记录原事件及所有未授权对象作为保留依据，不把“切鱼”抽象后改为另一种钩子。只有明确授权改剧情时，才提取获准重写的功能与节奏；不由模型重新出片推断创作权限。
7. 为裂变额外输出“允许改变／必须保持／因果适配候选”。适配候选只记录依赖，不自动授权；每项必须写成“新条件 → 失效的原假设 → 最小适配 → 仍锁定内容”，链路不完整时默认保持原样。
8. 区分纯视觉换景和环境条件变化。前者只换可见环境层；后者才标注保暖层、步态/发力、足迹、风力反应、受光或环境声等最小联动候选，同时锁住身份、目标、关键事件、切点和节奏落点。
9. 所有题材都登记“媒介类型 + 写实程度 + 人物比例 + 材质/光照”为来源风格锁；看不清写“未知”。用户未明确授权改画风时，换人物、场景、商品或玩法均遵守“写实不得推断成 3D/动画、3D 不得推断成真人实拍”，其他媒介同理。

## 完整时间轴与合规标记

完整母片单变量复刻不得只分析代表段。`full_timeline.json` 从 0 秒连续覆盖到解码末帧，
相邻范围严格相接；每项至少记录：

- `shot_id / start_s / end_s / source_cut / media_type`。
- 人物与可识别肖像、动作、相机、玩法因果、字幕/HUD、音频职责。
- `affected` 与 `affected_reason`，以及保留/替换职责。

真人实拍、可识别人脸或疑似真人肖像一律 `affected=false`，理由写明“合规直复用”；
不得把其人脸抽帧列为参考候选。明确非真人、卡通、游戏或风格化范围也只有在唯一变量
实际改变其可见玩法职责时才可 `affected=true`。边界不确定时按 `false` 处理并记录
未知，不用下游生成试探合规。

## 复刻元素提炼

拆镜同时输出“观察事实”和“可复刻 DNA”，两者不得混写：

- **观察事实**：原片实际出现的人物、事件、动作、接触、文字、声音、镜头和时间。
- **可复刻 DNA**：开场钩子机制、信息揭示顺序、情绪曲线、镜头功能、切镜密度、反馈频率、反转位置、高潮形式和 CTA 职责。
- 每个候选元素标明 `原样保留 / 保留功能并重写表现 / 放弃`。单变量复刻中未点名的内容默认原样保留；功能重写或放弃必须能追溯到用户授权，不能由“爆款 DNA”自行决定。
- “保留功能”不等于复制原事件。例如原片用巨兽攻击制造危机，新片可用资源告急制造同等强度钩子；只要节奏位置和叙事功能一致，不必保留攻击动作。
- 列出来源剧情的依赖链。若后续改变角色关系、场景规则、商品机构或事件结果，标明哪些原动作、字幕和反馈会随前提失效。
- 给出全片节奏骨架：前 `1–2 秒`核心事件、每段有效反馈数、最大空窗、转折和结尾落点，供重新写剧本时复用。

`script_from_breakdown.md` 只是来源内容的观察草稿。生成式重制不能把它直接改名为正式剧本，也不能只做名词替换；必须基于选中的复刻 DNA 另写完整主线和因果。

## 游戏观察重点

游戏素材重点记录：

- 玩家操作与自动行为分别是什么。
- 操作前状态、动作、反馈和动作后状态。
- 资源从哪里来、如何消耗；只知道增减量时不猜起止余额。
- 角色、敌人、建筑和资源何时出现、遮挡、出画、再入画或消失。
- 攻击、命中、受击、掉落、收集、建造和升级的先后。
- 地图地标、敌我方向、镜头跟随方式，以及世界对象和固定屏幕 UI 的区别。
- 全局昼夜与局部灯光分别记录；首次看到灯亮不等于知道它在画外何时点亮。
- 把人物/环境视觉身份与玩法状态机分开记录。玩法裂变可重建输入、动作、接触、反馈、资源、UI 和声音链，但人物身份、背景身份、镜头与节奏骨架仍是独立保留事实。

中段稳定画面可以标为设计锚点候选，但不能因此改成开场或倒置原事件。参考广告中的玩法也不能直接写成目标产品的已核准功能。

## 游戏逐段观察卡

每个连续时间段都从画面本身填写以下内容。不适用写“不适用”，看不清写“未知”，不能省略后让下游猜：

### 1. 场面与画风

- **场景类型与布局**：室内/室外、地图形状、道路/格子/平台/边界、入口出口、前中后景和固定地标。
- **美术媒介**：2D、2.5D、3D、写实、卡通、低多边形、手绘、像素等。
- **造型语言**：人物比例、轮廓、材质、建筑形状、道具尺度、敌我视觉区分。
- **颜色与光照**：主色、辅色、点缀色、饱和度、对比度、全局昼夜、天气、局部灯光与阴影方向。
- **画面密度**：主体占比、单位数量、背景动态、遮挡关系和安全区。

不要只写“卡通游戏风”“冰雪场景”。要写到第一次看片的人能重建这一段的空间和视觉规则。

### 2. 对象清单与状态

逐项登记当前可见对象：

- 玩家角色、敌人、NPC、建筑、塔、资源、掉落物、交互区和障碍物。
- 每个对象的身份特征、位置、朝向、数量、等级、持有物、可见状态。
- 对象何时进入、出画、被遮挡、再入画、生成、消耗、合并、破坏或升级。
- 画外对象只标“暂不可见”，除非有明确证据证明已经消失。

相同对象跨时间使用同一名称。对象数量发生变化时，记录变化前、触发、变化量和变化后；只看见其中一项就只写其中一项。

### 3. 人物与对象运动

把运动拆成可观察的机械过程：

- 起始位置和姿态。
- 起势、路径、方向、速度变化和停止位置。
- 关键移动的起止时刻、耗时，以及横向/纵向跨越画面宽高的近似百分比。
- 左右肢体、朝向、重心、接触点和受力对象。
- 与地面、障碍、敌人、道具和交互区的碰撞或遮挡。
- 头发、衣摆、武器、掉落物等次级运动。

“角色攻击敌人”不够。应记录谁从哪里面向哪里，以什么方式发射/挥击，弹道或武器经过哪里，何时命中，敌人如何受击以及掉落物落到哪里。

### 4. 速度与节奏测量

拆片复刻必须先观察原片速度，不能只写“快走”“快速攻击”“节奏紧凑”。时间精度受输入采样约束，4 fps 采样不能确认 0.1 秒级事件；未辨清的间隔给范围或写未知，不伪装成逐帧测量。需要更高精度时只复核相关短片段。

- **启动速度**：首个有效玩法动作或反馈发生时刻。
- **位移速度**：角色、敌人、弹丸、掉落物或吸附物每次运动的起止时间、起止画面位置、跨越屏幕宽/高比例和耗时；可换算为 `%屏宽/秒` 或 `%屏高/秒`。
- **动作速度**：瞄准、起势、发射、命中、拾取、放置、交付、建造和升级各自耗时。
- **事件频率**：攻击、命中、掉落、收集、合并等相邻事件间隔，以及单点和多点并发时每秒次数。
- **反馈密度**：每 `5 秒`有效动作/反馈次数、平均反馈间隔、峰值区间和最大无反馈空窗。
- **停顿**：区分操作停顿、观战停顿、转场和收尾；记录起止时间及期间是否仍有副主体运动或反馈。
- **镜头速度**：平移/跟随/缩放的起止时间、跨屏比例和每秒位移；固定镜头明确写 `0`。

最后输出该素材的“速度合同”：分别给出常规值、爆发值和最大空窗。不同玩法、不同运动主体分别测量，不能拿战斗冲锋速度代替经营走路，也不能把缩短总时长或增加独立事件数量当成提速。

复刻任务还要标出适合作为动态参考的 `2–5 秒`连续原子片段。片段从稳定状态前开始，在明确状态后结束，完整包含一次“动作→接触→反馈”，不得从动作中间起切，也不得为了凑高密度跨越镜头、转场或多个独立因果链。

### 5. 镜头与画面运动

镜头单独记录：

- 固定、跟随、平移、推进、拉远、旋转、升降、缩放或切镜。
- 镜头相对主体的前后左右、高低和俯仰角。
- 镜头运动开始/结束时刻、方向、速度和触发事件。
- 画面变化究竟来自拍摄机位、地图滚动、角色移动还是 UI 动画。

不得因为背景移动就直接判断镜头运动，也不得把跟随镜头写成固定机位。

### 6. 特效与反馈

特效不是“出现粒子”一句带过，至少记录：

- 触发源、出现位置、形状、颜色、亮度、方向、范围和持续时间。
- 属于瞄准、弹道、命中、受击、掉落、收集、建造、升级、奖励还是环境氛围。
- 特效与动作的先后关系，以及它是否改变对象状态。
- 屏幕震动、闪白、缩放、拖尾、冲击波、数字跳字和音效反馈分别出现在哪里。

装饰特效与玩法反馈分开。不能用粒子数量代替命中、收集或升级是否真正成立。

### 7. UI 与声音

- 固定 HUD 的锚点、内容、数值、按钮、进度条和安全区。
- 世界空间标签、飘字、血条、教学手势与屏幕 UI 分开。
- UI 数值变化对应哪个事件；看不清数值时只记录增减方向。
- 对白、旁白、BGM、点击、发射、命中、收集、建造和环境声按可辨程度记录。

声音不清晰时不要由画面推测。UI 位置固定不等于内容不变，内容变化和坐标变化分别记录。

## 因果链写法

每条关键玩法链使用：

`状态前 → 玩家输入/自动触发 → 主体动作 → 传播/接触 → 视觉与声音反馈 → 资源或对象状态后 → 下一目标`

一条链中任何环节不可见就标明缺口。不能从“最后出现奖励”倒推出前面一定完成了正确操作。

## 经验判断

接触印片必须同时读取面板索引与真实时间：按从左到右、从上到下的编号定位，不凭网格位置猜先后，不把多张印片当同一时间轴。出现首末状态矛盾时，仅复核对应原片短范围并修正观察账本，不反复全片重拆。动态天数/计数只转写可辨关键帧及变化范围，不虚构未采样的逐帧数字。

按以下顺序观察，能减少把结果当原因：

1. 先找本段开始时已经存在的人、物、资源和 UI。
2. 再找玩家输入或自动触发。
3. 接着记录动作传播，例如发射、移动、碰撞和命中。
4. 最后记录反馈、数量变化、奖励和下一目标。

镜头运动、游戏世界运动和 UI 动画必须分开。角色向右走不等于镜头向右移；HUD 抖动也不等于游戏地图移动。

稳定锚点优先选择主体、地图关系和操作区同时清楚的时刻，避开转场、爆炸遮挡、运动模糊、对象悬空/转化中和 UI 弹窗高峰。数量变化动作只能用稳定的动作前/后状态配对；瞬时帧只帮助观察，不能作为生成锚点或承担它之前发生的事件。

## 常见 bad case

- 固定机位长操作被切成多个“镜头”，下游误以为需要频繁切换机位。
- 角色出画后被写成消失，导致再入画时换人、复制或重置状态。
- 只记录“升级成功”，没有记录投入、触发动作和升级后的可见差异。
- 把全局入夜、建筑亮灯和材质换色合成一个事件。
- 看见数字变化却没看见来源，仍编造精确余额或收益公式。
- 把素材说明里的自动提示词当成视频事实，忽略真实画面冲突。
- 把来源剧情逐句搬进 `script_from_breakdown.md` 后直接当成新片剧本，没有区分可复刻功能与必须重写的具体事件。
- 用户只想复刻钩子和节奏，却把原角色关系、攻击动作、字幕和结局全部变成硬约束。

遇到这些问题时，只复核相关时间段；除非时间轴整体断裂，不重复拆整片。

## 质量门禁

- 没有有效段、时间断层、首尾范围不完整时不得交付。真实单镜头允许一段。
- 关键段缺场面、画风、对象、运动、镜头或特效描述时不得交付“详细拆镜”；只能标为待补观察。
- 观察不明可以留空，但不能编造；全局总结基于实际视频，推断与观察分开。
- 台词和画面文字只转写可辨内容。
- 可复刻 DNA 与观察事实分开，且每项都标明原样保留、保留功能重写或放弃。
- 已有可靠结果时只补缺失部分，不因一个字段不确定重复分析整片。
- 拆镜草稿不是正式剧本，不得冒充定稿。

## 回报

只报告分析范围、段数、总时长、观察异常和仍未知的信息，不替用户宣布后续创作模式或审批结果。
